## 2. 품질·보안 점검 사이클 (#154·#160) — v1.1 패턴 재현

code-analyzer·security-architect 병렬 점검(스프린트 28 PR 표면) → 적발·수정:

- **C1**: `insurance record()`의 `session.rollback()`이 인박스 savepoint 격리 무력화 — 경합 1건이 배치 전체를 오염시킬 수 있었음 → 자체 savepoint로 교체
- **H1**: invoice 경로 fee map의 code_type 소실 — **비급여 청구·약가초과 BLOCK이 수납창구 신호에서 침묵**(워크리스트와 불일치) → {price,cap,type} 계약 보존, 운영 실검증(P2026-0009 blocked:true)
- **H-1/H-2(보안)**: 외부 서버간 API 4종 접속기록 전무(열거 추적 불가) → record_access / 휴가 릴레이 SSRF 가드

- 잔여 중기 2건만: 연동키 도메인 분리·rate-limit (HIS 협의 필요)

## 4. progressive billing — 협의가 구현을 선행한 모범 사례

```
ERP 협의 회신(3건 확인 + lineId 안정성 1건 요청) → HIS P1: lineId=prescriptionId 정렬 → ERP 무변경 수용
→ P2(accrual 리스너) → 1차 E2E: rx 이벤트 2건 수신
   ✅ 멱등 실증 — 재소비 2회에도 invoice 완전 불변(199,966원 동결) = 이중과금 구조적 차단
   ⚠️ HIS 결함 적발 — emitAccrualLine 경로 unitPrice 미동봉(마스터 무가격 코드 0원 위험) → 회신
   ⏳ 스텝 ③정산 불변·④cancelled 제외 — HIS 발행 대기(자동 감시·도착 즉시 검증)
```
