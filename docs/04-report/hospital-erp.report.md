## 5. 배운 점 (Lessons Learned)

### 5.1 무엇이 잘 되었는가

1. **PDCA 사이클의 반복 설계**
   - Plan 7회→Design 4회→Check 3회+Act 3회를 통해 초반 87.2%에서 최종 90.7%로 개선
   - 각 회차마다 명확한 Gap 리스트를 작성해 다음 반복에 집중할 수 있었음
   - 버전 이력을 명시해 외부 피드백이나 조건 변경을 추적 가능하게 함

2. **설계-구현 동기화의 자동화**
   - design-validator(88점)와 gap-detector를 활용해 설계-구현 괴리를 정량화
   - Check #1에서 발견된 ACL Protocol, reprocess API 누락이 Act-1에서 신속하게 해소됨
   - 버전 컨트롤과 커밋 해시 추적으로 각 개선의 근거를 남김

3. **규제 도메인의 명시적 Gate**
   - Plan v1.2에서 G1~G5를 선언해 설계 착수 불가 항목을 명확히 함
   - 외부 의존(심평원 샘플, 간호등급 산식, DB 종류 등)을 명시해 "구현 가능 범위"의 경계를 그음
   - 사용자 측과의 협의 항목을 체계화

4. **보안을 설계 단계에 내재화**
   - FR-53(민감정보 필터), access_log 비동기, GCM·blind index, 백업 암호화를 설계에 명시
   - 코드 리뷰 검증 항목으로 설계에 기록 (예: WeasyPrint url_fetcher, Jinja2 autoescape)
   - 보안 검토(13건) 반영 → "구현 중 빠뜨리기 쉬운 항목"을 미리 설계로 정의

5. **한국 의료법 도메인의 복잡성 흡수**
   - 심평원 EDI 2025.3 종료 발견 → 설계 재조정
   - 전공의법(주80h)·근로기준법(주52h)·간호등급제 같은 특수 규제를 FR·테이블·로직에 분산 배치
   - 각 규제를 "Gate" 또는 "M0"로 분류해 우선순위 관리

### 5.2 개선 필요 영역

1. **외부 의존 항목의 사전 확보 실패**
   - M0a(HIS 연계 방식), M0c(통보서 샘플), M0d(양식) 미확정 상태로 설계/구현 진행
   - 향후: Phase 0 과제를 강제로 "구현 착수 전 완료" 체크포인트로 설정
   - 의존성 추적 도구(예: Make 또는 Just) 도입으로 선결 과제를 Gating

2. **프론트엔드 구현 속도의 불균형**
   - 백엔드 94.3% 대비 프론트 79.8% → 최종 통합 90.7%
   - 원인: 백엔드 라우트 설계(API-first)는 명시적이나 프론트 화면 설계가 상대적으로 덜함
   - 향후: "UI/UX Design" (§7.1)에서 26개 화면을 설계했으나 구현이 후행 → 구현 순서를 명시하고 스프린트 단위로 화면별 DoD 정의

3. **테스트 데이터 정책의 지연**
   - 합성 데이터 생성(script/seed_synthetic.py)은 "M1 산출물"로 미루어짐
   - 향후: 설계 완료 즉시 픽스처 생성 → 구현 초반부터 E2E 테스트 가능하게 진행

4. **Gate 해소 일정 공백**
   - M0a~M0g 중 M0b(인프라) 일부만 해소, 나머지는 "확정 대기"
   - 향후: Phase 0 과제 완료 여부를 주 1회 추적 → 의존 작업 지연 조기 발견

5. **어댑터 구현체의 사전 결정 부재**
   - ACL Protocol은 설계했으나 HIS 연계가 (파일 vs API vs HL7) 미확정 → 구현 시 블로킹
   - 향후: "M0a 미확정 시에도 Mock 어댑터는 먼저 구현" 규칙 추가 → 테스트·통합은 Mock으로 진행, 실연계는 M0 해소 후

### 5.3 다음에 적용할 사항

1. **Gate Ownership 명시**
   - 각 Gate마다 담당자(사용자 측·DB팀·법무 등)와 일정 할당 → 방치 방지

2. **외부 의존 항목의 우선순위 재분류**
   - **Critical**: Phase 1 착수 전 필수 (M0a, M0c, M0b-DB종류) → 병렬 진행
   - **High**: 구현 중 상세화 가능 (M0d, M0f, M0g) → 설계 심화 타이밍에 협의
   - **Medium**: Phase 2·3 (M0e 성능 기준) → 스프린트 단위 조정

3. **Phase 1/2 경계의 명확한 DoD**
   - 현재: "구현 가능 범위" 정의가 다소 흐릿함
   - 향후: 각 FR을 Phase 명시 + "Phase 1 DoD: 이의신청은 status 추적만, ABC 귀속은 Phase 2" 처럼 단계 내 명확화

4. **설계-구현 피드백 루프의 자동화**
   - design-validator + gap-detector + pdca-iterator를 매 스프린트 기말에 실행 → Match Rate 추이를 시각화
   - 90% 이상 유지 목표로 "기술부채 조기 상환" 규칙 도입

5. **규제 도메인 지식의 외부화**
   - Plan/Design에 "의료법 조항 번호·심평원 고시 링크·검증 방법" 명시 → 코드 리뷰 시 근거 제시
   - references/ 폴더에 "의료보험팀 인터뷰 기록·규제 변경 이력·FAQ" 관리
