## 2. 심사청구(요양급여비용) 회계 생애주기 A~E — v1.17.0~v1.19.0 (#615~624)

보험 청구가 발생·삭감까지만 회계 처리되던 것을 **지급·상태·재청구·정합·추정**까지 완결.

- **A. 공단 지급 대사**(#615): `ClaimPayment`(마이그 0155)·입금 DR1110/CR1140·variance(과소지급)·대사 요약.
  보험미수금(1140) 생애주기 **발생→삭감→지급** 완결.
- **B. 청구 지급 상태**(#617): `ClaimBatch.status`(DECIDED/PARTIALLY_PAID/PAID·마이그 0156)·미지급 조회.
- **C. 반송 재청구 추적**(#619): `ClaimResubmission`(마이그 0157)·미재청구 조회(수익 유실 방지).
- **D. 청구액 이중소스 정합**(#621): `ClaimSubmission`(마이그 0158)·제출 vs 심사대상 대사·미동봉 표면화.
- **E. 변동대가 재설계**(#623): 미결정 풀을 프록시→제출−결정으로 재정의·claim.reviewed decided 마킹으로
  실적(5910) 정렬(이중차감 제거)·decided_on as-of 재구성(마이그 0159). 계정 표시(5910) 현행 유지.

## 5. 방법론 — 도메인 심층 재검토 패턴

각 도메인을 5갈래(슬라이스)로 나눠 병렬 에이전트가 심각도순 findings 반환 → 종합·중복제거·**실코드 검증**
(PLAUSIBLE/오탐 기각) → 확증 결함을 심각도순 코herent PR로 보완(수정+회귀 테스트)→ CI→머지→릴리스→배포.
claims·환자 재검토가 각각 CRITICAL/HIGH 다수를 잡아냈고, 오탐(예: _eligibility_invalid coverage 기본값)은
검증 후 기각.
