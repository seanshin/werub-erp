# [ERP→HIS] W3.1 연동 요청 회신서 — 온보딩·ESS

> 대상: [W3.1 연동 요청서 v1.1](../../../../Hospital%20RUN/docs/04-report/features/w3.1-onboarding-ess-erp-request.md)
> 결론: **요청 1·2·3 구현 완료**(아래 상세), 요청 4 = (A) ERP 자체수집 채택, 요청 5 = 일부 확인·일부 스펙 회신 요청.

## 요청 1 (P0) — `staff.attendance_recorded` 수신: ✅ 구현

- **EP**: `POST {ERP_BASE}/api/v1/integrations/his/hr/webhook` (기존 게이트웨이, event만 추가 — 요청서와 동일)
- **봉투 호환**: HIS 공통 봉투 `{event, source, ref, occurredAt, payload}` **그대로 수신 가능**
  (ERP 표기 `{event_type, event_id}`와 양쪽 alias 처리)
- **멱등**: `ref`(=`att:{사번}:{YYYYMMDDHHmm}:{type}`) UNIQUE 인박스 — 동일 ref 재수신 시 `duplicate: true` 응답, 무시
- **처리**: 출퇴근 이벤트 → 일자행 페어링(IN=최초·OUT=최종, `correctionOf`=덮어쓰기,
  **자정 넘김 퇴근(12시 이전 OUT)은 전일 야간 교대에 자동 페어링**) → 월 근태 재집계(AttendanceSummary)
  → **급여 자동산정 반영**(야간·연장·근무일수 — ERP P1-② 기구현)
- **근태 원천 단일화(회신)**: **병원(HIS) 직원 = HIS 타임클럭 단일 원천 / Clinic 직원 = groupware 병행** 제안.
  일자행 식별을 `his:{사번}:{일자}` / `{clinicUserId}:{일자}`로 분리 저장하므로 충돌 없음.
  동일 직원이 양쪽에서 수신되는 경우만 합의 필요(권고: HIS 우선).

## 요청 2 (P0) — 급여명세 조회: ✅ (A) API 제공 + (B)도 가용

- **(A)** `GET {ERP_BASE}/api/v1/integration/hr/payslip?employeeNumber=&period=YYYYMM`
  (Header `X-Integration-Key` — webhook과 동일 키)
  - 응답: `{ employeeNumber, period, issued, gross, deductions[], net, items[], issuedAt }`
  - **확정분만** 노출(`issued:false` = 미확정/미생성) — 본인화면과 동일 정책
- **(B)** SSO 딥링크도 기가용: `https://his.example.org/erp/hr/payroll` (본인 명세, httpOnly 쿠키 인증)
- **원천징수영수증(연 단위)**: 데이터·계산은 보유(연말정산 모듈) — ESS 표기 항목 확정되면 동일 API 패턴으로 추가 제공 가능(후속 P1, 1일 내)

## 요청 3 (P1) — 연차 잔여: ✅ API 제공

- `GET {ERP_BASE}/api/v1/integration/hr/leave-balance?employeeNumber=&year=`
  → `{ employeeNumber, year, items:[{type:"ANNUAL", granted, used, remaining}] }`
- 산정: ERP 부여(근로기준법 §60 산정) − 승인(APPROVED) 사용분. HIS `LeaveBalance` 캐시 TTL은 HIS 재량(권고 ≤1h 또는 휴가결재 콜백 시 무효화)

## 요청 4 (정책) — 주민번호·계좌: **(A) ERP 자체수집 채택**

- **급여계좌**: ERP 보수 프로필(온보딩 보완입력 `/erp/hr/onboarding`)에서 수집 — 컬럼 암호화(AES-GCM·AAD=PK)·응답 마스킹·평문조회 API 없음 (기구현)
- **주민등록번호**: ERP는 현재 **미수집·미보유**(급여계산은 불요). 4대보험 EDI 신고 기능 도입 시점에
  별도 보안채널을 그때 합의(현재는 공단 신고서식 집계까지만 제공) → `staff.created`에서 제외 유지에 동의

## 요청 5 (확인) — 휴가 결재결과 → 급여: 부분 확인 + 스펙 요청

- **확인됨**: ERP는 W.Sign 결재 콜백 수신(`/api/v1/integrations/eapproval/callback`) →
  `leave_requests` 상태 반영 → 연차 잔여 즉시 갱신(요청 3 API에 반영) 기구현.
  승인 휴가의 급여 반영: 연차=유급(공제 없음), **무급휴가 공제 산식은 협의 필요**(일할 vs 시간할)
- **요청**: HIS가 기대하는 `callback_url` 회신의 **요청 봉투·서명 스펙 공유** 부탁
  (HR_LEAVE 결재요청이 ERP에 도달하는 경로의 payload 예시 — Clinic 요청서 사본 포함).
  수신 즉시 동일 패턴(X-Integration-Key)으로 회신 구현 예정

## 일정 회신 (§8)

- 요청 1·2·3: **운영 배포 완료 시점부터 즉시 스테이징 E2E 가능** — `출퇴근→근태→급여`, `휴가→결재→잔여` 시나리오 제안 동의.
  HIS 측 `/admin/erp` webhookUrl·키 설정 후 `staff.attendance_recorded` 송신 시작하면 됩니다.
