# ADR — 진료비 책정 SoT 결정 (D-6)

> **결정일**: 2026-06-11 | **결정자**: 운영자(사용자) | **상태**: ✅ 확정
> **선례**: D-2(인사 SoT — HIS=의료진·정규직 마스터, ERP=급여 전직원),
> eapproval-routing-decision(전자결재 HIS 경유)

## 결정

| 역할 | 담당 시스템 |
|------|------------|
| **접수·수납(창구 행위)** | **HIS 원무** — 환자 접수, 수납 처리·영수증 발급 |
| **진료비 책정** (수가 적용·급여/비급여 구분·본인부담 분리) | **ERP** |
| **사전 검토** (청구 전 삭감 위험 심사 — 워크리스트) | **ERP** (기구현, PR #136-#137) |
| **진료비 계산** (중간 진료비·퇴원 정산·청구액 산출) | **ERP** |

즉 **ERP가 진료비 계산 엔진**: HIS는 진료행위 발생 라인(원천 사실)을 ERP로 보내고,
ERP가 계산한 금액(중간/최종 진료비)을 받아 수납 창구에 표시·수납한다.

## 근거

1. **수가 마스터의 SoT가 이미 ERP** — 행위 161,735건 단가를 ERP가 HIS로 push(PR #80-82),
   시점별(진료일 as_of) 단가 이력도 ERP가 관리. 계산이 마스터 옆에 있어야 정합 보장.
2. **사전심사·삭감 분석이 ERP에 있음** — 책정과 사전검토가 같은 라인 데이터를 쓰므로
   한 시스템에서 처리해야 이중 계산·불일치가 없음.
3. **회계 연동** — 진료비 계산 결과가 곧 수익 인식·미수금의 원천. ERP 전표 체계와 직결.

## 흐름 (목표 아키텍처)

```
HIS 진료행위 발생 ──(라인 이벤트/조회)──▶ ERP 진료비 책정 엔진
                                            ├ 수가 적용(시점 단가) · 급여/비급여 · 본인부담 분리
                                            ├ 사전심사 워크리스트 자동 적재(동일 라인)
                                            └ 중간/최종 진료비 산출
HIS 수납 창구 ◀──(계산 결과 회신)────────────┘
   └ 수납 처리 → billing.settled 웹훅 → ERP 수익 전표 (기존 경로 유지)
```

## 영향·후속

- HIS 요청: 진료 라인 인터페이스 + 계산결과 수신 EP (요청서 `his-billing-lines.request.md`)
- ERP 구현(라인 스키마 합의 후): 본인부담 분리 룰, 중간계산서 발행, 책정 API
- 기존 유지: 수납·일마감 전표(billing.settled), EDIFACT 사후 결과 적재
- 미결: 산정특례·식대 등 본인부담 세부 룰은 원무·심사팀 협의로 파라미터화
