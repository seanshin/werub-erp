# 법정 파라미터 거버넌스 — 수당 설정·연 단위 갱신·변화 추적·로그

> 목적: 수당 단가·법정 요율(4대보험·소득세)이 "현재값 하나"로만 있어 (a) 개정 시 과거 급여 재생성이
> 소급 왜곡되고 (b) 연 단위(단협·고시) 갱신 이력이 없고 (c) 내년 갱신 누락을 사전에 못 보던 갭 해소.
> 2026-07-16(사용자 제안: "수당 설정·1년 단위 계약·법제화 변화 추적·로그 관리").

## 1. 구성 (v1.136)

### 1.1 수당 단가 기간화 — `hr.pay_rate_settings` (마이그 0200)
- `(rate_key, valid_from)` 기간 이력 구조. 연 단위 단협·취업규칙 갱신 = **새 발효행 추가**(기존 불변
  보존 = 변경 로그). 기존 행은 `valid_from=2020-01-01` 백필(무회귀).
- `load_rates(session, as_of)` — **급여월 기준 유효 단가**. 급여 생성(단건·벌크)이 급여월 1일을 전달
  → 단가 개정이 과거 급여 재생성을 왜곡하지 않음(소급 정확성).
- 이력 조회 `GET /hr/pay-rates/{key}/history`(발효일·금액·사유·변경자·변경시각) + AuditService 기록.

### 1.2 법정 파라미터 레지스트리 — `GET /hr/statutory-params`
- 4대보험 `RATES`·소득세 `TAX_PARAMS`(v1.135 연도화)의 **등재 연도·내년 준비 상태** + 수당 단가
  현황(발효일·이력 수) + 운영 노트(NP 상·하한 7월 고시 절차).

### 1.3 갱신 만기 사전 경보 — 컴플라이언스 만기 통합("법정 파라미터" 카테고리)
- **내년 RATES/TAX_PARAMS 미등재** → 연말(12/31) 만기 항목(D-90부터 노출). 미등재로 해를 넘기면
  급여·세액 계산이 fail-safe 예외로 정지하므로 사전 경보가 안전망의 짝.
- **국민연금 상·하한 7월 고시**(M-12) → 매년 7/1 연례 점검 항목.

### 1.4 평균임금 정밀화(M-13·동승)
- 퇴직충당·퇴직정산 평균임금 = 최근 **3개월** EARNING 평균(종전 1개월 — 상여·변동수당 월 왜곡).

## 2. 법제화 변화 추적의 경계(설계 원칙)

- **법정 요율·세법 파라미터 = 코드 상수 + 연도 키 + fail-safe**(v1.135) — 값 자체를 DB 편집으로
  열면 검증 없는 오입력이 급여 전체를 오염. 개정 반영은 코드 릴리스(리뷰·테스트 강제)로,
  **가시성(레지스트리)·만기 경보(컴플라이언스)** 만 시스템화.
- **수당 단가(단협·취업규칙) = DB 기간 이력** — 기관 재량 값이라 관리자 편집 + 발효일 + 불변 이력.
- 법령 원문 변화 감지는 기존 `공시·AI 색인`(regulatory/notices) 트랙이 담당(수가·고시 파싱).

## 3. 비범위
- 최저임금·통상임금 산입범위 등 추가 파라미터의 연도화(필요 시 TAX_PARAMS 패턴 복제).
- 법령 개정 자동 감지→파라미터 초안 생성(공시 AI 색인 고도화 백로그).
