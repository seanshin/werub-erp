# 급여명세서(임금명세서) 법정 부합 + 의료진 특화 기획서

> **요약**: 현행 급여명세 PDF(`payslip.html`)는 **항목코드·지급/공제·금액·합계**만 담아
> **근로기준법 §48②(임금명세서 교부 의무, 2021.11.19 시행)의 필수 기재사항 — 지급일·계산방법·
> 공제 산정근거 — 을 충족하지 못한다**. 이를 ① 법정 필수항목 부합, ② 항목 한글명·계산근거를
> 라인에 보존, ③ **의료진 특화 명세**(진료실적 배분·인센티브 산정식·계약 연동)로 확장하고,
> ④ 교부 이력·재발행·일괄 발행 등 운영 기능을 붙인다.
> **작성일**: 2026-07-08 · **버전** v0.1(초안) · **상태**: 기획(협의) · **우선순위**: High(법정 의무) ·
> **연관**: FR-07/FR-07b 급여, [[medical-staff-payroll-separation]](직종·고용형태 급여체계),
> [[physician-incentive-contract]](의료진 인센티브), hr.payroll_rules, hr.statutory, common.org_settings

---

## 1. 배경 / 요구

- **법정 의무**: 근로기준법 §48② 및 시행령 §27의2(2021.11.19 시행)는 **모든 사용자가 임금 지급 시
  임금명세서를 교부**하도록 의무화했다. 위반 시 500만원 이하 과태료. 필수 기재사항이 정해져 있어
  "항목·금액·합계"만으로는 **법적 명세서로 불충분**하다.
- **의료기관 특성**: 의료진 보수는 기본급 외 **진료실적 배분·성과 인센티브·당직/교대 수당**이 큰
  비중을 차지한다. 이 산정 내역이 명세서에 드러나지 않으면 분쟁·불신의 원인이 되고, 계약(연봉제·
  네트제·실적배분제)별 표기가 달라야 한다.
- **요구**: ① 법정 임금명세서 부합, ② 계산방법(연장·야간·휴일수당의 시간×통상임금×가산율) 표기,
  ③ 의료진 실적/인센티브 명세, ④ 교부·재발행·일괄발행 운영 기능.

## 2. 현황(ERP)과 공백

현재 `GET /hr/payrolls/me/{yyyymm}/pdf`(`my_payslip_pdf`) → `payslip.html` 렌더:

| 구성 | 현재 | 법정/의료진 공백 |
|------|------|------------------|
| 근로자 식별 | 성명·사번 | **생년월일**(동명이인 식별) 없음 |
| 지급일 | **없음** | 근로기준법 필수 — `PayrollRecord`에 지급일 컬럼 부재(`confirmed_at`만) |
| 임금 구성항목 | `PayrollLine.item_code`(BASE/OT/NIGHT…) **원본코드 노출** | **한글 항목명 없음**(카탈로그 부재) |
| **계산방법** | **없음** | 필수 — `payroll_rules.py`가 `연장=기본급/209h×1.5×시간` 계산하나 **라인에 근거 미보존** → 명세 표기 불가 |
| 공제 | 항목·금액·합계 | **산정근거**(보수월액·요율) 없음(4대보험·소득세 계산식) |
| 의료진 실적 | **없음** | 진료수익 배분·인센티브 산정식·계약 조건 표기 경로 없음 |
| 교부 | 본인 PDF 다운로드(PRINT 접속기록) | **교부 이력**(발급·수신확인) 없음·**일괄 발행**·재발행 정책 없음 |

**핵심 원인**: `PayrollLine`이 `(item_code, item_kind, amount)` 3필드뿐이라 **계산근거를 담지 못한다**.
계산 로직은 `payroll_rules.py`에 있으나 결과 금액만 라인화되어, 명세서가 "왜 이 금액인지"를 못 보여준다.

## 3. 법정 임금명세서 필수 기재사항 부합 (시행령 §27의2)

| # | 필수 항목 | 현재 | 조치 |
|---|-----------|------|------|
| 1 | 성명·생년월일·사원번호·직급 | 부분 | Employee에서 생년월일·직급 주입 |
| 2 | **임금 지급일** | ✗ | `PayrollRecord.paid_on` 신설 |
| 3 | 임금 총액 | ✓ | 유지 |
| 4 | 임금 구성항목별 금액 | 코드만 | 항목 카탈로그로 **한글명** 표기 |
| 5 | **임금 계산 방법**(항목별 계산식·특히 연장/야간/휴일: 시간수·통상임금·가산율) | ✗ | `PayrollLine.calc_basis`(JSON) 보존→표기 |
| 6 | **공제 항목별 금액·공제 총액**(필수) | 부분 | 공제 라인에 요율·기준액 근거(투명성 강화·계산방법은 지급항목 5호가 필수) |

> 계산방법은 "임금을 구성하는 각 항목에 대해 산출식 또는 산출방법을 기재"하되, 근로시간에 따라 달라지는
> 항목(연장·야간·휴일근로수당)은 **실제 근로시간수를 포함**해야 한다(고용노동부 지침). 공제는 항목별
> 금액·총액이 필수이며(§27의2 4호), 계산방법 필수 기재는 근로시간 연동 지급항목(5호)이 핵심 — 공제
> 산정근거는 투명성·분쟁예방 차원의 권장 강화분으로 본다.

**일용직·단시간 특례**: 이 ERP는 일용·계약·감시단속 직군을 직접 관리한다([[medical-staff-payroll-separation]]).
시행령 §27의2 단서상 **일용근로자는 생년월일·사원번호 등 일부 기재를 생략**할 수 있고, 계산방법도 근로
형태에 따라 완화된다(포괄·일당 정산). 명세서 생성 시 `employment_type`별로 필수항목 셋을 분기(일용=간이
양식·정규=전체)한다. 정확한 완화 범위는 노무 확인(§9).

**보존 의무**: 임금대장는 **3년 보존**(근로기준법 §42·시행령 §22). 임금명세서 자체 보존기간은 행정해석
영역이나, 교부 증빙·분쟁 대비로 임금대장에 준해 3년 이상 보존한다. 교부 이력(§7)과 확정 명세는
append-only로 보존하고, 재발행·정정은 원본을 남긴 채 버전화한다.

## 4. 데이터 모델 확장

```
PayrollRecord  + paid_on: date              # 임금 지급일(법정)
               + payment_method: str|null    # 계좌이체 등(선택)
PayrollLine    + item_name: str|null         # 스냅샷 한글명(카탈로그 폴백)
               + calc_basis: JSONB|null       # 계산근거 {qty, unit, rate, formula, base}
                                              # 예 OT: {"hours":10,"unit":"통상시급","base":9569,"rate":1.5}
                                              # 예 HI(건강보험·근로자부담): {"base":3200000,"rate":0.03545}
                                              #   ※ base는 계산에 실제 쓰인 기준액(라벨 정확·M5)·rate는
                                              #     근로자부담 요율(노사합산 아님·L1)
+ PayItemCatalog(code, name, kind, category, taxable, nontax_limit, display_order, is_medical)
                                              # 항목코드 마스터(SoT 단일화·표시순서·과세구분·비과세한도)
```

- `calc_basis`는 **표시 전용 근거**(회계 금액은 `amount`가 SoT). 라인 생성 시점(`payroll_rules`·
  인센티브 엔진)에서 함께 채운다. 없으면 명세서는 계산식 행을 생략(정직 — 소급 데이터 보호).
- `PayItemCatalog`로 원본코드→한글명·과세구분·표시순서를 단일 소스화(현 산재된 코드 리터럴 정리).

## 5. 직원(일반직) 급여명세서 강화

- **지급 구성**: 기본급 + 각 수당(항목명·금액·계산식). 연장/야간/휴일은 `calc_basis`로 "시간 × 통상시급 ×
  가산율" 행 노출.
- **공제 구성**: 국민연금·건강보험·장기요양·고용보험(보수월액×요율)·소득세(간이세액표)·지방소득세,
  각 산정근거 병기.
- **요약**: 지급 총액·공제 총액·실수령액 + 지급일·지급방법.
- **비과세 표기**: 식대 등 비과세 항목 구분(연말정산·과세 투명성).
- 기존 `payslip.html`을 항목명·계산식·공제근거·지급일 포함 레이아웃으로 개편(기관명은 현행
  `org_display_name` 유지).

## 6. 의료진 급여명세서 (특화)

의료진은 [[physician-incentive-contract]]·[[medical-staff-payroll-separation]] 산출물을 명세 항목으로 연결:

- **계약형별 표기**: 연봉제(월할)·네트제(공제 후 보장)·**실적배분제**(진료수익 × 배분율 − 원가). 계약
  조건 요약행(배분율·MG(minimum guarantee)·차감항목).
- **진료실적 배분 내역**: 해당 월 진료수익(외래/입원/검사)·공제(재료·위임경비)·배분 기준·산정 인센티브.
  `physician_revenue`·`incentive_engine` 결과를 `calc_basis`에 보존해 명세에 근거 표기.
- **당직·교대 수당**: `duty_service` 산출 근거(당직 횟수·단가).
- **개인정보 최소화**: 진료실적은 **본인 명세에만** 노출(부서장·타인 접근 차단 — 기존 hr.payroll 스코프
  + 본인 확인 경로 준수).
- **원천 구분**: 의료진·정규직 인사 SoT는 HIS(미러) — 명세용 실적/보상 데이터의 발신·계산 경계를 D-2
  역할분리에 맞춰 확정(§9 협의).

## 7. 관련 기능

1. **교부 이력·수신확인**: `PayslipIssue`(record_id·issued_on·**channel**(PORTAL·LINK·EMAIL)·acknowledged_at)
   — 법정 교부 증빙. 전자교부(포털 열람=교부 간주) 정책 명문화.
2. **명세서 출력**: 본인 PDF 다운로드(현행)·관리자 **일괄 발행**(월 확정분 전체 PDF 생성·묶음, hr.payroll
   write)·개별 재출력. A4 PDF(`render_pdf`) 단일 소스로 화면·링크·인쇄 일관.
3. **개별 확인 링크(교부 링크) 생성 ★**: 근로자별 **1회용/만료형 서명 토큰 링크**를 발급해, 본인이 로그인
   없이도 자기 명세를 **열람·진위 확인**하고 그 자체로 전자교부가 성립하게 한다.
   - **기반(선례 재사용)**: e-sign **참가자별 포털 토큰**(`integrations/sign_client.py` `portal_tokens`·
     `create_portal_request`·`sign_portal_base+url` deep-link, #482) 패턴을 급여명세에 이식 — 별도 SaaS
     불요 시 `common/security` 서명 토큰(대상월·employee 스코프·만료·1회성)으로 자체 발급.
   - **흐름**: 확정 → 근로자별 링크 생성 → 채널 전송(포털·이메일·SMS) → 열람 시 `PayslipIssue.
     acknowledged_at` 기록(=교부 증빙)·접근 감사(`record_access`).
   - **보안**: 토큰 단명·대상월 한정·서명(위조 방지)·재사용/만료 정책·타인 문서 접근 불가(employee 바인딩).
     PDF 문서 하단 **검증 QR/코드**(발급기관·대상월·지급총액 해시)로 오프라인 진위 확인 옵션.
3. **재발행 정책**: 확정 후 정정 시 버전 표기("정정 발행 v2")·사유·감사(현 `PayrollRecord` 확정 후 수정
   감사와 연계).
4. **연말정산·세무 정정 연계(M8)**: 기존 `/employees/{id}/year-end`·연간 총급여/기납부세액과 명세 합계
   정합 표시. **정정 발행·삭감 claw-back으로 지급/공제액이 바뀌면** 원천징수 재계산 + 이미 제출된 (간이)
   지급명세서 정정 필요 여부를 판정·플래그(세무 신고 연동은 후속).
5. **다월 요약(선택)**: 연간 지급/공제 추이(직원 셀프서비스).
6. **영문 명세서(선택)**: 발급기관이 **위루비병원**(국제진료·외국인 직원 가능)이므로, 항목
   카탈로그에 영문명(`name_en`)을 두고 언어 파라미터로 영문 PDF 발행. 금액·계산식은 동일, 라벨만 전환.

## 8. 회계 정합

- 명세서 **지급 총액·공제 총액**은 급여 전표와 대사되어야 한다. 단순 "명세 합계 ↔ 급여 voucher"는
  **오탐**을 낸다(H3): ① 성과급(INCENTIVE)은 급여 전표가 아니라 **별도 미지급 전표**(급여비용/미지급금)로
  올라가고, ② 명세 공제는 **근로자부담만**인데 전표엔 사업주부담·예수금이 섞인다. 따라서 대사 규칙 =
  **급여 voucher + 당월 승인 incentive voucher 합산** vs 명세, 공제는 **근로자부담 예수금만** 매칭(사업주
  법정부담 제외). 이 규칙으로 검산해 불일치 시 경고.
- 세무 base 정합(H1): 4대보험·소득세 계산 gross에 성과급 포함 여부가 명세 지급총액과 일치해야 한다
  (성과급 별도 생성으로 인한 base 누락 차단·§P2 1.5).
- `calc_basis`는 표시 전용 — 회계 금액은 `amount`(전표 SoT)와 항상 일치(이중 소스 금지).

## 9. 미결정 / 협의

- **통상임금 산정 ★**: 연장·야간·휴일 가산의 통상시급 기준(현 `기본급/209h`)은 **정기상여금·고정수당을
  누락**할 수 있다. **2024.12.19 대법원 전원합의체**가 통상임금의 '고정성' 요건을 폐기해, 재직·근무일수
  조건부 **정기상여금도 통상임금에 포함**될 수 있게 됐다(가산수당 산정에 직접 영향). 계산근거(`calc_basis`)
  표기의 정확성이 소송 리스크와 직결되므로, 통상임금 구성(기본급+포함대상 수당)의 산정 로직을 노무
  검토 후 `payroll_rules`에 반영하고 명세 계산식과 일치시킨다.
- **HIS SoT 경계**: 의료진 실적·인센티브 데이터의 계산 주체(HIS vs ERP). [[medical-staff-payroll-separation]]
  §3.5(D-2) 역할분리와 정합.
- **전자교부**: 근로기준법 §48② 본문이 전자문서 교부를 직접 허용(고용노동부 해석상 이메일·문자·사내
  전산망 게시도 교부 인정). 근로자 **개별 동의는 법정 필수 아님** — 사내 정책 옵션으로 둔다(§27의2는
  기재사항 조항이라 동의 근거로 인용하지 않음·M9).
- **비과세 항목 마스터**: 식대(월 20만)·자가운전보조금 등 **한도(`nontax_limit`)** 초과분 과세 분리(M4).
- **마이너스 실수령(L4)**: 대량 무급·claw-back 상계로 공제>지급이면 실수령 음수 — 근로기준법 §43(전액지급·
  압류 시 1/2 보호) 준거로 차기 이월 등 처리 규칙 필요(설계 미정).
- **과거분 재발행(L5)**: `paid_on=NULL` 과거 확정분을 재발행하면 지급일(필수) 없는 비적합 문서가 나온다 —
  재발행 시 실지급일/확정일 보정 입력을 강제.

## 12. 수용 기준

- [ ] 임금명세서에 **지급일·구성항목(한글명)·계산방법·공제 산정근거**가 모두 표기된다.
- [ ] 연장/야간/휴일 수당에 **근로시간수 × 통상임금 × 가산율** 계산식이 노출된다.
- [ ] 통상임금 구성이 노무 검토(2024 대법 판례 반영)와 일치하며 명세 계산식과 정합한다.
- [ ] **고용형태별 필수항목 분기**(일용=간이 양식·정규=전체)가 적용된다.
- [ ] 의료진 명세에 **진료실적 배분/인센티브 산정 내역**이 계약형에 맞게 표기된다(본인만).
- [ ] 명세 지급/공제 합계가 급여 회계 전표와 정합(불일치 시 발행 경고).
- [ ] 교부 이력·확정 명세가 **3년 보존**되고, 재발행·정정(버전·사유)이 원본 보존 후 감사된다.
- [ ] 계산근거 없는 과거 확정분은 계산식 행을 **생략**(허위 표기 없음).
