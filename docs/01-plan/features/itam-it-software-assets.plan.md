# IT 장비·소프트웨어 자산관리(ITAM) 기획서

> **요약**: 병원이 보유한 **IT 하드웨어(PC·노트북·서버·네트워크·의료 IT 기기·주변기기)** 와
> **소프트웨어·디지털 서비스**를 **운영 관점**으로 관리한다 — 무엇을 · 누가 · 어디서 보유하고,
> 언제 도입·배정·반납·폐기했으며, **보증/만기·갱신·컴플라이언스·비용**은 어떤지. 소프트웨어·서비스는
> 과금 구조가 제각각이라 **① 구매 소프트웨어(영구 라이선스) ② SaaS 구독 ③ AI 구독 ④ 클라우드 사용
> (사용량 과금)** 을 **하나의 모델로 유형화**해 다룬다. 기존 재무 자산(`finance.FixedAsset`·
> `IntangibleAsset` = 감가상각·회계)과 **중복하지 않고 연결**하며, 배정·생애주기·라이선스 준수·**구독 갱신·
> 클라우드 비용**을 담당한다. 자산 태그(바코드)·도입 결재·구매 증빙·만기 대시보드·회계 비용은 **기존
> 인프라를 재사용**한다.
> **작성일**: 2026-07-09 · **버전**: v0.2(검토 보완) · **상태**: **구현 완료(M1~M4·v1.35.0~v1.40.3 LIVE)**
> — 릴리스 리포트 `docs/04-report/erp-itam-release.report.md`. 잔여=조달 PO 연계·Shadow-IT AP 대사(heavier).
> **우선순위**: Mid-High(보안·감사·라이선스 법적 리스크·의료 IT 통제)
> **v0.2 변경**: 재사용 주장 코드 검증(§8)·병원 특수성 갭 반영(PHI·의료기기·환율·분실도난)·
> **등록 워크플로(QR 태그·사진 증빙·계약서 등록)** 추가·과대 재사용 주장 정정(마감 체크리스트·이상탐지=신규).
> **연관**: finance(FixedAsset·IntangibleAsset·감가상각·비용/예산·BI 지출마트), app(컴플라이언스 만기
> 대시보드), scm(바코드·라벨·워크스테이션), 결재선 엔진, 범용 첨부(Attachment), hr(직원·부서 배정),
> 마스터코드(asset)

---

## 1. 배경 / 문제

- **IT 자산이 대장으로 관리되지 않는다** — 어떤 직원이 어떤 노트북·PC를 쓰는지, 서버·네트워크 장비가
  어디에 몇 대 있는지, 언제 도입했고 보증이 언제 끝나는지 흩어져 있거나 엑셀·수기.
- **소프트웨어·서비스 유형이 다양해 한 틀로 관리되지 않는다** — ① 구매 SW(영구 라이선스·좌석 수) ②
  SaaS 구독(월/연·좌석·자동갱신) ③ AI 구독(좌석형 + 사용량/토큰 혼합) ④ 클라우드 사용(IaaS/PaaS·사용량
  과금·고정 좌석 없음). 과금·갱신·수량 개념이 제각각인데 흩어져 있어 **전사 소프트웨어·서비스 인벤토리**가 없음.
- **라이선스 컴플라이언스 공백** — 보유 좌석(seats) 대비 실제 설치·사용이 추적되지 않아 **과소 라이선스
  (under-licensing)** 법적 리스크, **과다 구매** 낭비.
- **구독·클라우드 비용 가시성 부족** — 자동갱신 구독의 **갱신·해지 통보 기한** 누락(원치 않는 갱신·서비스
  중단), **클라우드 변동비**(월별 사용량)·구독료가 부서/프로젝트별로 집계되지 않아 **IT 지출(OPEX) 통제 불가**.
- **보안·감사 요구** — 병원 IT는 환자정보·의료정보를 다루므로 **자산 통제(누가 무엇을 보유)** 와
  **폐기 시 데이터 소거 증빙**이 감사·정보보호 요건. 현재 추적 수단 없음.
- **회계와 운영의 분리** — `finance.FixedAsset`은 **감가상각·재무제표**용(취득원가·내용연수·손상·재평가)
  이라 **배정·위치·보증·라이선스 준수** 같은 운영 정보를 담기에 부적합. 저가·소모성 IT 장비는 재무자산
  등재 대상도 아님. **운영 대장이 별도로 필요**.

## 2. 현황 자산 (재사용 기반)

| 기존 | 무엇 | ITAM에서의 역할 |
|------|------|------------------|
| `finance.FixedAsset`·`DepreciationEntry` | 유형자산 회계·감가상각(취득원가·내용연수·상태·부서) | 고가 IT 장비는 이 **재무자산과 연결**(FK)해 감가상각은 finance가, 운영은 ITAM이 — 중복 입력 없음 |
| `finance.IntangibleAsset` | 무형자산 상각(SW 자본화분) | 자본화 SW는 라이선스와 **연결** |
| **컴플라이언스 만기 대시보드**(`app.compliance`) | 면허·계약·방사선장비·재고 유효기간 만기 크로스도메인 집계 | **SW 라이선스 만기·장비 보증 만기**를 신규 소스로 추가(기존 뷰에 통합) |
| **결재선 엔진**(다단계 승인) | PO·계약·의료계약 공통 승인 | **자산 도입/폐기 승인**에 재사용(금액 임계 룰) |
| **범용 첨부**(Attachment·sha256) | 증빙 파일 보관 | 구매 계약서·라이선스 증서·폐기(데이터 소거) 확인서 첨부 |
| **바코드·라벨·워크스테이션**(scm) | 품목·로트 바코드·라벨 출력·스캔 작업대 | **자산 태그(asset tag) 바코드·라벨**·모바일 카메라 스캔으로 실사 |
| hr(Employee·Department)·마스터코드(asset self-code) | 직원·부서 마스터·자산 자체코드 회신 | 자산 **배정 대상**·부서 위치·HIS 자산코드 상관 |
| RBAC·감사(AuditService) | 권한·접근기록 | 신규 스코프 `itam.assets`·전 변경 감사 |

> **핵심**: 감가상각(회계)·만기 대시보드·결재·첨부·바코드는 **이미 있다**. ITAM은 **운영 대장(하드웨어
> 인벤토리+배정+생애주기)** 과 **SW 라이선스 준수**라는 신규 도메인을 더하고, 나머지는 재사용·연계한다.

## 3. 갭 분석 (신규 필요)

- **G-1 IT 하드웨어 대장** — 자산 태그·분류(노트북/데스크톱/서버/네트워크/프린터/모바일/의료IT/주변기기)·
  시리얼·모델·제조사·상태(재고/배정/수리/폐기)·위치·도입일·보증만기·사양(JSON).
- **G-2 배정 생애주기** — 직원/부서 배정·반납 이력, 현재 보유자 추적, 인수인계·퇴사 연계.
- **G-3 소프트웨어·서비스 마스터(4유형)** — 구매 SW·SaaS·AI 구독·클라우드를 **유형 필드로 유형화**한 단일
  마스터(과금 유형·좌석/사용량·벤더 계정·정기료·갱신·라이선스 키 암호화).
- **G-4 좌석 배정·라이선스 준수** — 좌석형(구매 SW·SaaS·AI 좌석) 할당 → **보유 vs 사용 대비**(초과=위반·
  미사용=절감 대상). 사용량형(클라우드)은 비대상.
- **G-5 만기·갱신·보증 연계** — 구독 만기·**자동갱신 해지 데드라인**(만기 − 통보일수)·장비 보증 만기를
  **컴플라이언스 만기 대시보드**에 노출.
- **G-6 유지보수·수리 이력** — 수리·정기점검·업그레이드 기록(일자·벤더·비용).
- **G-7 폐기·데이터 소거** — 폐기 시 데이터 소거 확인서 첨부·감사(보안 요건).
- **G-8 구독·클라우드 비용/사용량 원장** — 정기 구독료 + **클라우드/AI 사용량 변동비**를 월별로 집계 →
  IT 지출(OPEX) 리포트(유형·벤더·부서별)·예산 대비·회계·BI 연계.
- **G-9 비용 주기 점검·변동 감지** — 변동이 심한 클라우드/AI 비용을 **월별로 확인·검토**하는 정기 워크플로
  (미입력 체크리스트·전월 대비/예산 대비 이상 경보·배치 스케줄·책임자 리뷰·대시보드/알림).
- **G-10 등록 워크플로(QR·사진·증빙)** — 등록 시 **QR 태그 발번·출력·재스캔 조회**·**실물/시리얼 사진·구매
  증빙 첨부**. QR 생성기 신규(1D는 기존 jsbarcode).
- **G-11 벤더·계약 연계** — 자산·서비스↔구매/유지보수(AMC)/구독 계약 연결·**계약서 등록**(CLM 재사용 또는 경량).
- **G-12 PHI·보안·의료기기 속성** — PHI 취급 플래그·암호화/백신·보안등급, **분실/도난 상태→유출 신고**,
  **수리반출·재배정 시 소거 게이트**(폐기에만 걸지 않음), UDI/품목허가/교정 만기(비방사선 의료 IT).
- **G-13 네트워크 1급 필드·좌석 메트릭 정확도** — IP/hostname/MAC를 1급 필드화(중복 IP 탐지), 좌석
  메트릭(per-core/CAL/concurrent·user vs device)로 준수율 오계산 방지.
- **G-14 조달·퇴사·Shadow-IT·초기 이관** — PO→입고→자산 자동 생성, 퇴사자 좌석/계정 회수, 지출 대사로
  미등록 SaaS 발견, 기존 엑셀 자산대장 **벌크 임포트**(FortuneSheet 그리드 재사용·serial dedup).

## 4. 목표 / 범위

**목표**: IT 관리자가 **하드웨어·소프트웨어 자산을 한 곳에서** 등록·배정·추적하고, **라이선스 준수와
보증/구독 만기**를 놓치지 않으며, **감사·보안 요건**(누가 무엇을 보유·폐기 증빙)을 충족한다.

**범위(M1) — IT 하드웨어 대장·배정**: 자산 등록·분류·태그(바코드)·상태·위치·직원/부서 배정·반납 이력·
보증만기. `finance.FixedAsset` 선택적 연결.

**범위(M2) — 소프트웨어·디지털 서비스**: 4유형(구매 SW·SaaS·AI 구독·클라우드)을 **단일 서비스 모델**로
등록 — 과금 유형(영구/좌석 구독/사용량)·벤더/계정·**좌석 배정·준수율**·**갱신(자동갱신·해지통보 기한)**·
**비용(정기료 + 클라우드 월 사용량)**·**월 비용 주기 점검·변동 감지**·만기를 **컴플라이언스 대시보드**·
**회계 OPEX**에 통합.

**범위(M3) — 운영 심화**: 유지보수/수리 이력·도입/폐기 **결재선**·폐기 데이터소거 **증빙 첨부**·
**워크스테이션 카메라 스캔 실사**(자산 태그).

**비범위(후순위)**: 엔드포인트 에이전트 자동 수집(설치 SW 미터링)·네트워크 디스커버리(자동 인벤토리)·
MDM/EMM 연동·RFID·SaaS 계정 프로비저닝 자동화. (M1~M3은 **수기·바코드 기반 대장**; 자동수집은 별건.)

## 5. 핵심 기능 / 데이터 모델(초안)

### ① IT 하드웨어 자산 — `itam.it_assets` (G-1)
`asset_tag`(QR/바코드·unique)·`name`·`category`·`serial_no`(unique·dedup)·`model`·`manufacturer`·
`status`·`owner_department_id`(소유/위치 부서)·`assigned_employee_id`(현재 사용자)·`location`·
`acquired_on`·`warranty_until`·`spec`(JSON: CPU/RAM/디스크)·`finance_asset_id`(FK→FixedAsset)·
`contract_id`(FK→벤더 계약·§⑤b)·`note`. 상태 전이 가드(배정→반납·수리반출·폐기 승인).

- **상태(status)**: IN_STOCK · ASSIGNED · REPAIR · **LOANER**(대여) · **LOST/STOLEN**(분실·도난) ·
  RETIRED · DISPOSED. LOST/STOLEN은 PHI 장비면 **유출 신고 트리거**(G-12).
- **네트워크 속성 1급 필드**(JSON 아님·쿼리·중복 IP 탐지): `ip_addr`·`hostname`·`mac_addr`.
- **보안/PHI 필드**(G-12): `handles_phi`(환자정보 저장/처리)·`security_grade`·`disk_encrypted`·`av_installed`
  — 개인정보 안전성 확보조치 감사 증빙·소거 우선순위.
- **의료기기 속성**(category=MEDICAL_IT·G-13): `udi`(UDI)·`mfds_no`(품목허가번호)·`calibration_due`
  (정도관리/교정 만기→대시보드). 방사선장비는 기존 regulatory 유지, 그 외 의료 IT 계열 대응.
- **소유 부서 vs 배정 대상 분리**: `owner_department_id`(위치/소유)와 `assigned_employee_id`(사용자)를
  구분(검토 지적 — 개념 혼재 방지).

### ①b 자산 등록 워크플로 — QR 태그·사진 증빙·계약서 (G-10·요구사항)
등록을 **한 흐름**으로: 기본정보 입력 → **QR 태그 발번·출력** → **사진/증빙 첨부** → **계약 연계·계약서 등록**.

- **QR 코드 출력·등록**: 등록 시 `asset_tag`로 **QR 코드 라벨 생성·인쇄**(자산 부착용). 이후 **QR 재스캔**으로
  즉시 조회·실사(모바일 카메라 스캔 v1.34.0의 `qr_code` 포맷 재사용). 라벨=QR + 자산명·태그·부서.
  - 구현 주의: QR 이미지 생성 라이브러리 필요(클라 자체 렌더·외부 CDN 금지). 기존 `jsbarcode`는 1D 전용
    → **QR 생성기 추가**(예: qrcode·자체 번들). 바코드(1D) 병기 옵션.
- **사진·증빙 첨부**(등록 시): 자산 **실물 사진·시리얼 라벨 사진·구매 증빙**을 등록 단계에서 첨부.
  범용 첨부(`entity_type=it_asset`) 재사용 — 신규 entity_type·행 가드 등록(§8 첨부 판정).
- **계약 연계·계약서 등록**(G-11): 등록 시 **구매/유지보수 계약(벤더·기간·금액·SLA)** 을 연결하고
  **계약서 문서 첨부**. 자산 ↔ 계약 관계로 보증·유지보수·갱신을 계약 기준으로 관리(§⑤b).

### ② 배정 이력 — `itam.asset_assignments` (G-2)
`asset_id`·`employee_id`·`assigned_on`·`returned_on`·`assigned_by`·`acknowledged_at`(수령 확인·
chain-of-custody)·`return_condition`·`note`. 현재 보유자 = open(반납일 없음) 행. **퇴사(offboarding)
연계**: hr 퇴사 이벤트 시 미반납 HW + open **SaaS 좌석**(§④)·계정을 회수 대상으로 플래그(G-14).
수리 반출·재배정·반납 시 **PHI 잔존 소거 확인 게이트**(G-12·폐기에만 걸지 않음).

### ③ 소프트웨어·서비스 마스터 — `itam.software_services` (G-3)
구매 SW·SaaS·AI·클라우드를 **단일 테이블 + 유형 필드**로 유형화(과금 구조 차이를 필드로 흡수).

| 필드 | 설명 |
|------|------|
| `name`·`vendor`·`edition` | 제품/서비스명·벤더·에디션(예: Microsoft 365 E3, AWS, ChatGPT Team) |
| `service_type` | **PERPETUAL_SW**(구매 SW) · **SAAS**(SaaS 구독) · **AI_SUBSCRIPTION**(AI 구독) · **CLOUD**(클라우드 사용) · **OPEN_SOURCE** |
| `billing_model` | **ONE_TIME**(영구) · **SEAT_RECURRING**(좌석 구독) · **USAGE_METERED**(사용량·클라우드/AI API) |
| `billing_cycle` | ONE_TIME · MONTHLY · ANNUAL · USAGE (변동) |
| `seats`·`license_metric`·`alloc_basis` | 보유 좌석(좌석형만) · 메트릭(PER_SEAT/PER_CORE/CAL/CONCURRENT) · 할당 기준(USER/DEVICE) — 준수율 정확도 |
| `unit_cost`·`recurring_cost`·`currency` | 좌석 단가 / 정기 청구액(월·연) / 통화(USD 구독 대응) |
| `vendor_id`·`account_ref`·`portal_url`·`contract_id` | 거래처 마스터·벤더 계정/테넌트 ID·콘솔 URL·계약(§⑤b) |
| `owner_employee_id`·`cost_center` | 서비스 책임자·비용 귀속 부서/코스트센터 |
| `started_on`·`expires_on` | 도입일·만기(구독/유지보수·영구는 NULL) |
| `auto_renew`·`cancel_notice_days` | 자동갱신 여부·해지 통보 필요일수(→ 해지 데드라인 산출) |
| `license_key_enc` | 라이선스 키(구매 SW·AES-GCM 컬럼암호화·마스킹 조회) |
| `intangible_asset_id` | FK→IntangibleAsset(자본화 SW 회계 연결·nullable) |

> **유형별 처리 차이**: 구매 SW=좌석 준수(④)·만기 없음 · SaaS/AI 좌석형=좌석 준수+갱신+정기비용 ·
> AI/클라우드 사용량형=**좌석 개념 없음**, 대신 **월 사용량·비용(⑤)** 으로 추적.

### ④ 좌석 배정·라이선스 준수 — `itam.service_allocations` (G-4·좌석형)
`service_id`·`it_asset_id`|`employee_id`·`allocated_on`·`released_on`. **준수율** = open 할당 수 vs `seats`
(초과 시 위반 경보). SaaS/AI 좌석형은 **미사용 좌석(할당 없음)** 도 표시 → 다운그레이드·비용절감 근거.
사용량형(클라우드)은 좌석 없음 → 이 표 비대상.

### ⑤ 구독·클라우드 비용 원장 — `itam.service_costs` (G-8·비용/사용량)
`service_id`·`period`(yyyymm)·`amount`·**`currency`·`fx_rate`·`amount_krw`**(클라우드/AI는 USD 청구 →
ERP FX 인프라로 KRW 환산)·`usage_note`(vCPU-h·토큰·GB)·`source`(수기/청구서/API). 월별 실비 + 정기
구독료를 집계 → **IT 지출(OPEX) 리포트**(유형·벤더·부서별)·예산 대비·회계 반영.
- **finance 연계**: `VoucherService`(source_module=`itam`·source_ref=`service_cost:{id}:{period}`·멱등)로
  OPEX 전기, `VoucherLineDTO.department_id`로 **부서 배분**. **예산 대비**는 `budget_service`(Budget/
  Encumbrance 3-way) 재사용. **AP/매입 전표와 대사**(이중계상 방지·매칭 규칙).

### ⑤b 벤더·계약 연계 — `itam.vendor_contracts` (G-11·요구사항)
자산·서비스를 **벤더 계약**과 연결하고 **계약서를 등록**해 보증·유지보수·갱신을 계약 기준으로 관리.

- **계약 마스터**: `vendor_id`(거래처 마스터 참조·정규화)·`kind`(PURCHASE 구매/AMC 유지보수/SUBSCRIPTION
  구독/SLA)·`title`·`start_on`·`end_on`·`amount`·`sla_note`·`note`. `it_assets.contract_id`·
  `software_services.contract_id`가 이 계약을 참조(다대일).
- **계약서 등록**: 계약서 PDF를 첨부(`entity_type=itam_contract`). **위수탁/구매 계약 생애주기(CLM)** 가
  이미 있으면 그 계약을 참조(재사용), 아니면 경량 계약 레코드로 시작(협의·§8).
- **만기·갱신**: 계약 `end_on`·자동갱신·해지 데드라인을 **컴플라이언스 대시보드**(§⑧)에 노출.

### ⑥ 비용 주기 점검·변동 감지 — `itam.cost_reviews` (G-9·**핵심**)
클라우드·AI 비용은 **변동이 심해** 정적 원장만으로 부족 — **월별로 확인·검토하는 정기 작업**을 워크플로화.

- **월 점검 사이클**: 매월 마감 시 사용량형(CLOUD·AI)·구독 비용 **입력·확인 체크리스트** 생성(미입력 서비스
  목록 제시). 책임자(`owner_employee_id`)가 확인(attestation) 기록. ⚠ **신규 구축**(재무 마감 체크리스트는
  코드에 없음 — HR 온보딩의 "누락 항목 식별" 발상만 참고).
- **변동 감지(경보)**: 서비스별 **전월 대비 증감률**·**직전 N개월 이동평균 대비 이탈**·**예산 대비 초과**가
  임계 초과 시 경보. 급증(예: 클라우드비 +40%)·급감(구독 해지 누락/유령 구독)·예산 소진을 자동 플래그.
  ⚠ **변동감지 알고리즘은 신규 구현**(기존 감사 이상탐지는 전표 Benford/중복 전용·시계열 로직 없음). 검토
  **상태 워크플로**(PENDING/FLAGGED/CONFIRMED)만 `AuditReviewService` 패턴을 템플릿으로 참고.
- **Shadow-IT 발견**(G-14): finance 지출(카드·AP 거래처) vs 등록 서비스 **대사** → 미등록 SaaS 자동 플래그
  (에이전트 없이 가능·자동수집과 무관).
- **정기 실행**: **배치 워커(worker-batch)** 가 월초/주간 스케줄로 점검 실행 → 미입력·이탈·만기 임박을
  집계해 **컴플라이언스 만기 대시보드**와 **알림**으로 통지(책임자·IT관리자).
- **추이·리뷰 화면**: 서비스/벤더/부서별 월 비용 추이(스파크라인)·예산 대비·이상 표시·미사용 좌석 →
  **분기 리뷰**(다운그레이드·해지·통합 의사결정)의 근거. BI 마트로도 노출.
- **모델**: `cost_reviews`(`period`·`service_id`·`prev_amount`·`amount`·`delta_pct`·`status`
  PENDING/FLAGGED/CONFIRMED·`reviewed_by`·`note`) — 점검 이력·이상 처리 상태 보존.

> **요지**: "**원장에 쌓기**"가 아니라 "**주기적으로 확인·이상 감지·책임자 리뷰**"가 비용 관리의 핵심.
> 배치·이상탐지·마감 체크리스트·대시보드·알림을 재사용해 **월 점검을 자동 유도**한다.

### ⑦ 유지보수 이력 — `itam.maintenance_records` (G-6)
`it_asset_id`·`kind`(REPAIR/INSPECTION/UPGRADE)·`on_date`·`vendor`·`cost`·`note`·증빙 첨부.

### ⑧ 만기·갱신·보증 연계 (G-5)
`compliance_service`에 소스 3종 추가 — **구독 만기**(`expires_on`)·**자동갱신 해지 데드라인**
(`expires_on − cancel_notice_days` · 해지하려면 이 날짜 전 통보)·**장비 보증 만기**(`warranty_until`).
기존 만기 대시보드(기한형 items)에 자동 노출·정렬. 자동갱신 건은 "갱신 예정" 톤 구분.

### ⑨ 화면 — `/assets/it`·`/assets/services`·워크스테이션 스캔 실사
- `/assets/it` 하드웨어 대장·배정(목록·필터·상세·배정 이력·유지보수·바코드 라벨).
- `/assets/services` **소프트웨어·서비스** — 유형 탭(구매 SW·SaaS·AI·클라우드)·좌석 준수(사용 n/보유 m·
  미사용 강조)·갱신 캘린더·**월 비용/사용량 추이**·벤더/부서별 지출.
- **모바일 카메라 스캔**(v1.34.0 재사용)으로 하드웨어 실사(스캔→자산 확인·위치/보유자 갱신).

### ⑩ 권한·감사
신규 스코프 `itam.assets`(IT 관리자 read/write)·조회 read·전 변경 감사(배정/폐기/키 접근). 라이선스 키·
계정 시크릿은 평문 조회 없이 마스킹(계좌·주민번호 패턴 재사용).

## 6. 우선순위 / 로드맵

| 단계 | 내용 | 산출물 |
|------|------|--------|
| **M1** | IT 하드웨어 대장·배정(수령확인)·**QR 태그 발번/출력/재스캔**·**사진/증빙 첨부**·**벤더 계약 연계·계약서 등록**·PHI/보안/네트워크 1급 필드·분실도난 상태·보증만기(→대시보드)·**엑셀 벌크 임포트** | `it_assets`·`asset_assignments`·`vendor_contracts`·화면·QR·첨부·마이그 |
| **M2a** | 소프트웨어·서비스 마스터(4유형·좌석 메트릭·벤더/계약)·좌석 배정·준수율·**갱신/해지 데드라인**(→대시보드)·키 암호화 | `software_services`·`service_allocations`·화면·마이그 |
| **M2b** | **구독·클라우드 비용 원장**(정기료+사용량·**환율 KRW**)·**월 주기 점검·변동 감지·경보**(배치·대시보드·알림)·**Shadow-IT 대사**·OPEX 리포트·예산·회계(전표/AP 대사)/BI 연계 | `service_costs`·`cost_reviews`·배치·리포트·마이그 |
| **M3** | 유지보수 이력·도입/폐기 결재선·**소거 게이트(수리반출·재배정·폐기)**·데이터소거 증빙·워크스테이션 QR 실사 | `maintenance_records`·결재 연동·첨부·스캔 |
| **M4** | 조달(PO→입고→자산 자동생성)·**퇴사 좌석/계정 회수**·의료기기 규제 속성(UDI·교정)·KPI(활용률·낭비·MTBF·교체계획) | scm/hr 연계·규제 필드·리포트 |

각 단계 독립 배포 가능(M1만으로도 자산 대장 가치). 대시보드 연계는 M1(보증·계약)·M2a(구독 갱신)에서.
비용 가시성(M2b)은 클라우드·AI 지출이 큰 경우 우선순위 상향 가능. **High 리스크 필드(PHI·분실도난·환율·
좌석 메트릭·소유vs배정 분리)는 M1/M2 데이터 모델에 선반영**(후속 마이그 비용 절감·§8).

## 7. 전제 / 외부 의존 · 결정 필요

- **자동 수집 여부** — M1~M3은 **수기·바코드 대장**. 설치 SW 자동 인벤토리(에이전트)·네트워크 디스커버리는
  **별건**(도구·에이전트 배포 필요) — 도입 여부는 별도 결정.
- **클라우드/AI 비용 입력 방식**(M2b) — 월 사용량·청구액을 **수기/청구서 입력**으로 시작, 이후 벤더 비용
  API(AWS Cost Explorer·CSP 청구서 등) **자동 수집**은 후속(벤더별 커넥터). 어디까지 자동화할지 결정.
- **OPEX 회계 반영 수위** — 구독·클라우드 비용을 ITAM 원장 관리만 할지, **finance 비용 전표·예산**까지
  연동할지(정기 비용 인식·부서 배분) 재무팀 협의.
- **회계 연결 정책** — 고가 IT 장비를 `FixedAsset`에 이중 등재 대신 **ITAM에서 등록→재무자산 연결(FK)**
  로 할지, 임계금액 이상만 연결할지 결정(재무팀 협의).
- **HIS 자산코드 상관** — HIS가 자산코드를 쓰면 마스터코드(asset self-code) 매핑 여부(현재 ERP 자체코드 회신 중).
- **라이선스 키 보관 수위** — 키 컬럼 암호화(권장) vs 미보관(외부 볼트) 결정.
- **폐기 데이터 소거 표준** — 소거 방식·확인서 양식(정보보호 정책 연계). **소거 시점**=폐기+수리반출+재배정.
- **QR 생성기 선정** — 클라 자체 렌더(외부 CDN 금지) QR 라이브러리 번들(1D는 기존 jsbarcode 재사용).
- **계약 연계 원천** — 벤더 계약을 **기존 CLM(위수탁/구매 생애주기) 재사용** vs ITAM 경량 계약 레코드 신설.
- **PHI 분류 기준·거래처 마스터** — PHI 취급 판단 기준(정보보호팀)·`vendor_id` 거래처 마스터 정규화 범위.
- **초기 데이터 이관** — 기존 엑셀 자산대장 벌크 임포트 범위·serial 중복 정합 규칙.

## 8. 검토 반영 (v0.2) — 재사용 주장 코드 검증·정정

코드 검증 결과, **견고한 재사용**과 **정정 필요(과대 주장)** 를 구분한다. High 리스크 필드는 M1/M2 모델 선반영.
