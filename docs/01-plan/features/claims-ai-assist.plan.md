# 사전심사 AI 보조 — 검토 가능성 평가 + AI 서버 활용 재기획

> **목적**: (1) 현재 심사 검토 화면으로 실제 보험심사가 가능한지 평가, (2) AI 서버(weve RAG) 호출로
> 심사를 돕는 기능을 재검토·기획. 휴먼인더루프·비식별·판단보류 원칙 유지.
>
> **작성**: 2026-06-14 | **상태**: 기획(코드 미구현) | **선행**: ai-diagnose·ai-search(구현됨)

---

## 1. 현재 심사 검토 가능성 평가

### 화면이 제공하는 것
- **검토(case-detail)**: 적발(룰·코드·진료일·위험액·결정 인정/오탐)·상태전이·과거 삭감이력·메모
- **명세(statement)**: 라인별 계산(단가×횟수·종별가산·본인부담)·단가 근거(고시 시행일)·적발 연결·자격기반 본인부담·AI 근거·의료진 질의

### 심사 유형별 가능성
| 심사 유형 | 가능? | 근거 |
|----------|:---:|------|
| **형식·산정 심사** (산정횟수·중복·코드유효·단가·종별가산) | ✅ **가능** | 룰 적발 + 명세 계산분해 + AI 산정기준 고시 근거 |
| **자격·본인부담 심사** | ✅ **가능** | 명세에 자격기반(자동차보험·자격상실 등) 본인부담 SoT 표시 |
| **의학적 타당성** (예: N0983011 3회가 다발성 골절로 정당한가) | ⚠️ **부분** | 상병(진단)·시술부위·진료기록 = HIS EMR 임상정보 필요 — 화면엔 없음. **의료진 질의(협업 루프)로 우회** |

### 결론
- **형식·산정·자격 심사는 이 화면으로 가능** — 룰+명세+AI 고시근거로 "산정기준 위반 여부" 판단.
- **의학적 타당성은 임상정보(상병) 부재로 직접 판단 불가** → 의료진 질의로 간접 해결(현 구조). HIS EMR 상병코드 연동 시 직접 보조 가능.
- **현 한계**: AI 근거가 **명세 라인별 수동 클릭** — 케이스 단위 "이 적발들을 인정할지/오탐인지" **종합 판단 보조가 약함**. 심사자가 적발마다 일일이 AI를 눌러야 함.

## 2. AI 서버(weve RAG) 활용 — 현황 재검토

### 구현됨
- `ai-diagnose`(POST): 청구코드별 삭감위험 + 고시 근거 인용 + 권고. **판단보류**(근거 없으면 hold·환각방지). 코드 type→notice_type 필터.
- `ai-search`(GET): 공시·산정기준 자유질의(RAG).
- **안전장치**: `filter_gate`(비식별 PII 차단)·판단보류·휴먼인더루프·weve 키 게이트·감사.
- 수가책자 전문 적재(89건, weve 색인).

### 갭 (지금 못 하는 것)
1. **케이스 종합 AI 검토 없음** — 적발마다 수동. 케이스 열어도 AI가 전체를 한 번에 진단·권고 안 함.
2. **적발↔근거 자동 연결 없음** — 적발 옆에 해당 산정기준 고시가 자동으로 안 붙음(클릭 필요).
3. **오탐 사전 제안 없음** — AI가 "이건 오탐 가능성 높음 + 사유 초안"을 미리 제시하지 않음(심사자 전수 판단).
4. **삭감 방어/소명 초안 없음** — 인정 적발의 이의신청·소명 근거를 AI가 안 써줌.
5. **의료진 질의 초안 없음** — 무엇을 물어야 할지 AI가 안 만들어줌.
6. **임상 컨텍스트 미투입** — 상병코드 등이 AI에 안 들어가 의학적 판단 정확도 한계.

## 3. 기획 — AI 보조 기능 (휴먼인더루프 전제)

> 모든 제안은 **AI=제안, 결정=심사자**. 비식별 입력(코드·산정내역·룰·금액·상병코드만, 자유문 PII는
> filter_gate 차단)·판단보류(근거 없으면 표시 안 함)·감사 로그 유지.

| # | 기능 | 설명 | 가치 |
|---|------|------|------|
| **A1** | **케이스 1-클릭 종합 AI 검토** | 검토 패널에서 "AI 종합검토" 1회 → 케이스의 **모든 적발을 배치 진단** → 적발별 {위험도·고시근거·권고(인정/오탐)·confidence}를 인라인 표시 | 적발마다 수동 클릭 제거, 종합 판단 가속 |
| **A2** | **적발별 근거 자동 첨부** | 각 적발에 관련 산정기준 고시(제목·시행일·발췌)를 자동 인용 — 클릭 없이 | "왜 이게 위반인지/예외는 뭔지" 즉시 |
| **A3** | **오탐 사전 제안 + 사유 초안** | AI가 오탐 가능성 높은 적발에 ⚠️ "오탐 후보" + **사유 draft** 제시 → 심사자 1-클릭 확인 | 룰 캘리브레이션 가속, 전수판단 부담↓ |
| **A4** | **삭감 방어/소명 초안** | 방어 가능한 적발에 이의신청·소명 근거 draft(고시 인용 포함) | 삭감 대응 문서화 자동화 |
| **A5** | **의료진 질의 초안 자동** | 적발 기반 "무엇을 물어야 하는지" 질의문 draft → 협업 루프 1-클릭 발송 | 의학적 보완 가속 |
| **A6** | **임상 컨텍스트 투입** | HIS EMR 상병코드(진단)를 비식별로 AI에 투입 → 의학적 타당성 판단 정확도↑ | 의학적 심사 직접 보조 |

### 데이터 흐름 (A1 예시)
```
케이스 적발들(코드·산정 N회·룰·위험액 — 비식별) [+ 상병코드(A6)]
   → filter_gate 비식별 검증
   → weve diagnose(batch) — 적발별 평가
   → ERP: 판단보류 필터(근거 없는 건 표시 제외)
   → 검토 패널 인라인 표시 {위험도·근거·권고·confidence}
   → 심사자 인정/오탐 결정(휴먼인더루프) → 캘리브레이션 피드백
```

## 4. 우선순위·단계 (ERP 단독 vs 외부)

| Phase | 기능 | 전제 | 비고 |
|-------|------|------|------|
| **P1 (즉시·ERP 단독)** | A1 종합검토 + A2 근거 자동첨부 | weve 키(운영 보유)·기존 ai-diagnose batch화 | 가장 큰 체감, 신규 외부 의존 없음 |
| **P2** | A3 오탐 제안·사유 초안 | diagnose 응답 recommendation→오탐후보 매핑 | 캘리브레이션 효과 |
| **P3** | A4 방어 초안 · A5 질의 초안 | weve 생성 프롬프트 추가(요청) | 문서화 자동화 |
| **P4 (외부 합류점)** | A6 임상 컨텍스트 | **HIS EMR 상병코드 연동**(비식별 전달 합의) | 의학적 정확도 — HIS 협의 |

### 권장 시작점
**P1 (A1+A2)** — 기존 `ai-diagnose`를 **케이스 단위 배치 호출**로 확장하고, 응답을 검토 패널 적발 옆에
인라인 표시. weve 키만 있으면 ERP 단독 구현 가능하며, "적발마다 수동 클릭" 한계를 바로 해소.

## 5. 안전·거버넌스 (불변)
- **비식별**: filter_gate(주민번호·차트번호·전화 탐지 차단). AI엔 코드·산정내역·금액·상병코드만.
- **판단보류**: 근거 고시 인용 없으면 AI 결과 표시 안 함(환각 방지). 로컬 룰만 신뢰.
- **휴먼인더루프**: AI는 위험도·근거·권고·초안까지. **인정/오탐·소명·발송은 심사자**.
- **감사·캘리브레이션**: AI 호출·심사자 결정 감사 로그, 오탐률→룰 보정 피드백.
- **법적효력 없음 표기** 유지(보조 도구).
