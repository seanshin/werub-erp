# Plan — 보험심사팀 워크리스트 + 심화 사전심사 (claims-worklist)

> **배경**: `/erp/claims/pre-review`는 룰엔진 1회 실행→결과 표시(무상태)로, 심사팀의
> 실제 업무(차트별 목록·담당 배정·검토 진행·결정 기록)를 담지 못하고, 룰도 샘플 4종에
> 그쳐 심사 깊이가 얕음. 사전심사를 **심사팀 워크플로 시스템 + 심화 룰 체계**로 확장하고,
> 도구 스프레드시트(FortuneSheet+Recharts, PR #134)를 심사 작업면으로 적극 활용.
>
> **레벨**: Enterprise | **상태**: 기획 v0.2 (2026-06-11, v0.1 검토보완) | **승인 대기**

## 1. 사용자와 문제 (보험심사팀)

| 페르소나 | 현재 불편 | 목표 |
|----------|----------|------|
| 심사 담당자 | 실행 결과 휘발·재탐색 불가, 엑셀로 이중 작업 | 워크리스트 추적 + **시트 붙여넣기→즉시 평가** |
| 심사 팀장 | 배정·처리량·적체 불가시 | 배정·진행률·위험액 대시보드 |
| 청구 담당 | BLOCK 차트 수정 완료 여부 확인 불가 | 수정요청→재검→해소 파이프라인 |
| 진료과/원무 | 반복 삭감 패턴 피드백 없음 | 룰 적중률·진료과별 위험액 환류 |

## 2. 차트 케이스 파이프라인 (v0.1 유지)

```
사전심사 실행 ──저장──▶ PreReviewCase (chart_no×진료월 멱등 upsert)
  OPEN → IN_REVIEW(담당 배정) → CLEARED | FIX_REQUESTED | BLOCKED
                                   └ 재실행 재평가 → 해소 finding 자동 RESOLVED
  finding 결정: PENDING → ACCEPT(수정 필요) | DISMISS(오탐+사유)   ← 룰 캘리브레이션 데이터
```

## 3. 심화 사전심사 — 룰 체계 3단계 (v0.2 신규)

### Tier 1 — 정형 룰 확장 (즉시 구현, 엔진 evaluator 추가)
기존 4종(중복·산정횟수·미등재·금액이상)에 더해:
| 룰 | 검증 내용 | params 예 |
|----|----------|----------|
| `AGE_SEX_LIMIT` | 수가·약가의 연령/성별 적용 제한 | `{code:"...", min_age, max_age, sex}` |
| `EXCLUSIVE_PAIR` | 동시산정 불가 조합(같은 날 A+B 청구 불가) | `{codes:["A","B"]}` |
| `PERIOD_LIMIT` | 주/월/연 단위 산정 상한(기존 일 단위 확장) | `{max, window:"M"}` |
| `SURCHARGE_CHECK` | 야간·공휴 가산 적정성(진료시각 대비) | `{rate, hours}` |
| `LOS_RATIO` | 내원/요양일수 대비 행위량 이상 | `{per_day_max}` |
- 룰은 전부 **PreReviewRule 테이블 행 추가만으로 활성화**(엔진 무수정 원칙 유지).
- 라인 입력 스키마 확장: `birth_date|age, sex, treated_at(시각), visit_days` 선택 필드.

### Tier 2 — 자사 데이터 기반 심화 (보유 데이터로 즉시)
1. **삭감 이력 컨텍스트**: 기존 EDIFACT 적재분(`claim_statements`+`claim_adjustments`)에서
   동일 chart_no(환자) 과거 삭감 이력·진료과 삭감률·조정사유 분포를 케이스에 자동 부착 —
   "이 환자/진료과는 최근 n건·m원 삭감" 컨텍스트로 검토 우선순위 판단 지원.
2. **통계적 금액 이상치**: 코드별 우리 병원 청구 분포(p95) 대비 이상 라인 적발
   (현 고정 tolerance 룰의 데이터 기반 심화).
3. **위험액(risk amount)**: finding별 관련 청구액×심각도 가중 합계 = 케이스 정렬 기본축
   ("위험액 큰 차트부터").

### Tier 3 — 외부 데이터 합류 시 (기존 백로그 연결)
- 고시 세부룰(D41 협의), DUR 병용금기 마스터(공공 API 키 채널), **G1 통보서 실삭감 ↔ 케이스
  chart_no 매칭 → 룰별 예측 적중률 자동 산출**(weve 캘리브레이션 라벨과 합류).

### 룰 관리 탭 (심사팀 셀프서비스)
- 룰 목록·on/off·심각도·params(JSON 폼) 편집 — `PUT /claims/pre-review/rules/{id}` (ADMIN, 감사).
- 통계 탭의 룰별 오탐률(DISMISS율)을 옆에 표시 — 조정 근거를 한 화면에서.

## 4. 스프레드시트 적극 활용 (v0.2 신규 — PR #134 자산 재사용)

| 통합점 | 동작 | 재사용 |
|--------|------|--------|
| **시트 → 평가** | HIS에서 뽑은 청구 엑셀을 도구 시트에 붙여넣기 → "시트에서 사전심사" 버튼 → 헤더 매핑(차트번호·코드·진료일·횟수·금액·연령·성별) → lines 변환 → 평가+케이스 저장 | `sheetToGrid` |
| **케이스 → 시트** | 케이스 상세 "시트로 열기" — 해당 차트 청구 라인 + 적발 라인 **셀 하이라이트**(FortuneSheet cell style), 심사 메모 열 추가 후 xlsx 반출(반출 감사) | `toSheet`·excel.py |
| **워크리스트 → 시트** | 필터된 워크리스트 전체를 시트로 — 팀 회의용 일괄 검토·코멘트 후 일괄 상태반영(시트 왕복: 상태 열 수정→재업로드) | `toSheet`/`sheetToGrid` |
| **통계 차트** | 통계 탭에 `SheetChart`(Recharts) — 룰별 적발·오탐률, 진료과별 위험액, 월별 추이. 데이터는 시트로도 동시 제공(심사팀 가공 자유) | `SheetChart` |

설계 원칙: 스프레드시트는 **입출력 작업면**(심사팀의 엑셀 습관 수용), 정본은 케이스 DB.
시트 왕복 반영은 chart_no 키 매칭·검증 후 적용(불일치 행은 스킵 리포트).

## 5. 데이터·API (v0.1 + 확장)

- 마이그 0038: `pre_review_cases`(+ **risk_amount**, dept_code, care_month) ·
  `pre_review_findings`(+ resolved, line_ref) · `pre_review_comments`
- API: v0.1의 7종 + `PUT /rules/{id}`(룰 관리) + `POST /cases/bulk-status`(시트 왕복 일괄) +
  `GET /cases/{id}/sheet`·`GET /cases/export.xlsx`(시트/반출) + stats에 위험액·진료과 축 추가
- 정책: `claims.review` 재사용, 룰 관리는 write=ADMIN

## 6. 웹 — `/erp/claims/pre-review` 탭 5종
① **워크리스트**(기본): 위험액 정렬·상태 칩·필터(내 담당/고위험/미배정) + "시트로 열기"
② **케이스 상세**: finding 인정/오탐(사유)·삭감 이력 컨텍스트 패널·상태 전이·코멘트·시트 열기
③ **실행**: 기존 + **시트 붙여넣기 평가**(헤더 매핑 미리보기)
④ **통계**: SheetChart(룰별·진료과별·추이) + 시트 동시 제공
⑤ **룰 관리**: on/off·params·심각도 + 오탐률 병기

## 7. 비범위 (후속)
HIS EMR 차트 딥링크, 알림센터 연동, SLA 타이머, DUR 마스터(키 채널), G1 자동 적중률(통보서 수신 후 — 데이터 합류점만 이번에 마련).

## 8. 검증
- 단위: 신규 evaluator 5종(경계값), 케이스 멱등·해소 마킹, 상태 전이 규칙, 시트 헤더 매핑·왕복(불일치 스킵), 위험액 집계, 삭감 이력 컨텍스트 집계
- 라우트 스모크 + Zero Script QA 시나리오: 시트 붙여넣기→평가→배정→오탐 처리→재실행 해소→통계 반영

## 9. 일정
PR 2개 분할: **PR-A** 케이스 파이프라인+Tier1 룰+워크리스트/상세/실행 탭,
**PR-B** Tier2(삭감 컨텍스트·위험액·통계)+시트 통합+룰 관리 탭. 각 1세션 내.
