# 기획 — 심사 케이스 진료비 명세 상세 + 심사팀↔의료진 협업 (삭감 방지 루프)

> 상태: **Plan v0.2** (방향 확정 — 구현 대기) · 2026-06-12 · 대상: `/erp/claims/pre-review`
> 선행: 심사 워크리스트(PR #136·137·150·165), D-6 진료비 엔진(PR #138~144), 사전심사 룰 10종
>
> **확정 결정(2026-06-12)**: ① 본인부담률 **전체 정밀화**(기관종별·산정특례·의료급여 종별) —
> 단 외부 데이터 의존분 분리(§2.1) ② 의료진 채널 **P2 ERP 내부 / 릴레이 P3** ③ 질의 단위 **적발+라인 둘 다**

## 1. 배경·목표

### 사용자 요구
> "검토 버튼 외에 **상세 버튼**을 누르면, 각 세부 오더·재료·수가코드 등 디테일하게
> **계산 수식과 계산 방식, 본인부담금 구성**이 디테일하게 나와서 확인 가능한 화면.
> 향후 보험심사팀이 체크하고 **의료진과 소통해서 삭감되지 않은 결과물**을 만드는 기능으로 확장."

### 한 줄 목표
심사 케이스를 "적발 목록"에서 **"왜 이 금액인지 완전히 추적 가능한 진료비 명세 + 의료진과 합의해 삭감을 사전 제거하는 협업 작업대"**로 확장.

### 현재 공백 (as-is)
| 영역 | 현재 | 공백 |
|------|------|------|
| 케이스 상세 | 적발(findings)·코멘트·과거삭감 이력 | **진료비 라인·계산 과정·본인부담 분해 없음** |
| 진료비 계산 | `invoice` API에 라인별 분리 존재 | 케이스 화면과 **분리**(심사팀이 못 봄), 코드명·수식 설명·codeType 구분 부족 |
| 적발↔라인 | finding에 code만 | **어느 라인이 왜 위험한지** 시각적 연결 없음 |
| 의료진 소통 | 케이스 코멘트 1종(내부) | **라인 단위 질의·의료진 회신·수정 반영 루프 없음** |

## 2. 핵심 개념 — "심사 가능한 진료비 명세"(Auditable Billing Statement)

케이스(chart_no × care_month)에 대해 **라인 → 계산 → 본인부담 → 적발 → 협업**을 하나의 트리로 통합.

```
케이스 P2026-0022 (2026-05 · 외래 · NHIS)
├─ 진료비 요약: 청구 781,685 / 본인부담 312,674 / 보험자 469,011 / 비급여 0  [기수납 0 → 수납예정 312,674]
├─ 라인 명세 (오더/수가/약제/재료별)
│   ├─ [수가] AA257 야간가산 ×3   단가 85,000(ERP마스터)  = 255,000
│   │        └ 계산: 255,000 × 외래40% = 본인 102,000 / 보험 153,000
│   │        └ ⚠️ 적발: 산정횟수 초과(상한1, 실3) · 위험액 170,000 [BLOCK]
│   │           └ 💬 심사메모·의료진 질의 (아래 4)
│   ├─ [약제] M047802 ×21   단가 0(미해소·HIS폴백 대기)  = 0  ⚠️ 단가 미동봉
│   └─ [재료] ...
└─ 협업 타임라인: 심사팀 질의 → 의료진 회신 → 수정/근거 → 해소
```

## 2.1 본인부담률 전체 정밀화 (확정 ① — 데이터 경계 주의)

현재 `billing_engine.split_line`은 외래 40% 단일. **전체 정밀화**로 확장하되, 입력 데이터 출처가 다름:

| 정밀화 축 | 방식 | 데이터 출처 | 즉시 가능? |
|----------|------|------------|:--------:|
| **기관 종별** (의원30·병원40·종합50·상급60) | **설정 마스터(런타임 변경·시점관리)** — 기본 `HOSPITAL`(병원 40%). 향후 종별 변경 시 effective_from 신규 행 → 과거 진료는 당시 종별로 계산 | **ERP 설정** | ✅ 즉시 |
| **산정특례** (암5·희귀난치10·중증화상5 등) | 특례 등록별 본인부담률 — 환자/라인에 특례 플래그 + 특례유형 필요 | **HIS 데이터 대기** (BillingLine에 special_case·특례코드 필드 신설 → HIS 동봉 요청) | ⚠️ 외부 |
| **의료급여 1·2종** | 1종 0%·2종 일부 정액 — coverage=MEDICAL_AID에 종 구분 필요 | **HIS 데이터 대기** (급여종 필드) | ⚠️ 외부 |
| 식대·비급여·자보·산재 | 기존 분기 유지 | 현재 보유 | ✅ |

→ **전략**: 엔진을 풀 정밀 구조로 한 번에 확장(기관종별 설정 + special_case_type·medical_aid_class 인자 수용)하되,
HIS 미동봉분은 **현행 기본값으로 안전 폴백**(특례 미표기=일반율, 의료급여=0%). 동시에 **HIS에 필드 동봉 요청서** 발송.
화면은 "적용 본인부담률 + 근거(기관종별/특례/급여종)"를 명시해 데이터 도착 시 자동 정밀화.

**기관 종별 설정 마스터** (`InstitutionGradeSetting` — `pay_rate_settings` 시점관리 패턴):
- 필드: `grade`(CLINIC/HOSPITAL/GENERAL/TERTIARY), `outpatient_rate`, `effective_from`, `created_by`
- 기본 시드: `HOSPITAL` 40%, effective_from=2026-01-01
- `load_billing_rates(session, as_of)` → 진료일 시점 유효 종별의 외래율을 `split_line(rates=...)`에 주입
- 종별 변경 = 신규 행(effective_from) → **과거 진료는 당시 종별로 정확 계산**(소급 오류 방지)
- 외래 외 율(입원20·식대50·특례5)도 같은 설정에 두어 운영 조정 가능(기본값=현행)

## 3. 기능 명세

### F1. "상세" 버튼 → 진료비 명세 탭 (검토 버튼과 분리)
- 워크리스트 행에 **검토**(기존 — 적발 결정 작업대) + **상세**(신규 — 진료비 명세) 2버튼
- 상세는 별도 라우트(`/claims/pre-review/cases/{id}/statement`) 또는 케이스 카드 내 탭 전환
- **검토 = 적발 처리 / 상세 = 금액 근거 확인** 으로 역할 분리 (사용자 의도)

### F2. 라인별 계산 투명성 (핵심)
각 라인을 펼치면 **계산 과정을 수식 그대로** 노출:
```
청구금액 = 단가 × 수량       255,000 = 85,000 × 3
  └ 단가 출처: ERP 마스터(우선) | HIS 산정가(폴백) | 미해소(0원)
본인부담 = 청구 × 본인부담률   102,000 = 255,000 × 40%
  └ 본인부담률 근거: 외래 40%(NHIS·병원종별) | 입원 20% | 식대 50% | 산정특례 5% | 비급여 100% | 자보·산재·의료급여 0%
보험자부담 = 청구 − 본인부담   153,000
```
- **codeType 분류 그룹핑**: 수가(TARIFF)·약제(DRUG)·재료(MATERIAL)·비급여(NONCOVERED) 섹션별 소계
- 본인부담률은 `billing_engine.split_line`의 분기를 그대로 라벨화 — 엔진=SoT, 화면은 설명만(중복 계산 금지)
- 스프레드시트 반출(심사팀 친화 — 기존 시트 인프라 재사용)

### F3. 적발 ↔ 라인 연결
- 라인에 해당 코드의 적발 배지 인라인 표시(BLOCK 빨강/WARN 주황)
- 적발 클릭 → 룰 근거(detail) + AI 삭감위험 평가(ai-diagnose, 산정지침 인용) + 과거 동일코드 삭감 이력
- "위험액 = 이 라인이 삭감되면 잃는 금액" 명시

### F4. 라인/적발 단위 심사 메모 + 의료진 질의 (확정 ③ — 적발+라인 둘 다)
- 질의 대상 = **적발(finding)·라인(code) 둘 다** — 적발 없는 일반 라인에도 질의 가능
  (예: 룰이 못 잡았지만 심사자가 의심하는 고가 비급여)
- `ClaimReviewQuery.finding_id`(nullable)·`line_code` 조합으로 대상 표현
- 심사팀 → 의료진 **질의 생성**: "AA257 3회 산정 근거 요청 — 산정기준 1회 초과"
  - 질의 상태: OPEN → ANSWERED → ACCEPTED/REVISED
- 의료진 알림 채널은 **P2=ERP 내부 화면 목록**(확정 ②) — 릴레이는 P3

### F5. 의료진 회신 → 삭감 방지 루프
```
심사팀 위험 식별 → 의료진 질의 → 의료진 회신(근거 제시 | 오더 수정)
  ├ 근거 제시 → 심사팀 검토 → 적발 DISMISS(오탐, 사유=근거) → 케이스 청구 유지
  └ 오더 수정 → HIS 라인 변경 → 재동기화 → 적발 해소 → 삭감 위험 제거
최종: 케이스 CLEARED(이상없음) — "삭감되지 않을 청구"로 확정
```
- 의료진 회신은 **감사 추적**(누가·언제·근거) — 향후 실제 삭감 시 책임소재·학습 데이터

## 4. 데이터 모델 (신규 — 최소)

| 엔티티 | 용도 | 핵심 필드 |
|--------|------|----------|
| `ClaimReviewQuery` | 라인/적발 단위 의료진 질의 | case_id, finding_id?, line_code, status(OPEN/ANSWERED/ACCEPTED/REVISED), question, raised_by, assigned_to(의료진) |
| `ClaimReviewReply` | 의료진 회신 | query_id, body, reply_type(EVIDENCE/REVISE), author, created_at |

- 진료비 명세는 **신규 테이블 없이** invoice 엔진 재사용(아래 5) — 라인은 BillingLine이 SoT
- 라인 메모는 ClaimReviewQuery(question만 있고 assigned 없는 내부 메모)로 통합 가능

## 5. API (신규/확장)

| 메서드·경로 | 내용 |
|------------|------|
| `GET /claims/pre-review/cases/{id}/statement` | **진료비 명세** — 케이스 chart_no×care_month로 BillingLine 조회 → `compute_invoice`(라인별 분해+계산 메타) + 라인↔적발 매핑 + codeType 그룹 소계 |
| `POST /claims/pre-review/cases/{id}/queries` | 의료진 질의 생성 |
| `POST /claims/pre-review/queries/{qid}/replies` | 의료진 회신 |
| `PATCH /claims/pre-review/queries/{qid}` | 질의 상태 전이 |

- `billing_service.invoice`에 **care_month 필터** 추가(현재 chart 전체 — 심사는 월 단위) → statement가 재사용
- 계산 메타는 엔진이 라인별로 `{rate, rate_basis, formula}`를 함께 반환하도록 확장(split_line 결과에 설명 필드)

## 8. 미해결 질문

### ✅ 결정됨 (2026-06-12)
- **본인부담률 정밀도** → 전체 정밀화(기관종별 즉시 + 특례·의료급여종별은 HIS 데이터 도착 시, §2.1·P1.5)
- **의료진 질의 채널** → P2 ERP 내부 화면 / P3 알림 릴레이
- **질의 대상** → 적발+라인 둘 다(F4)

### ⏳ 잔여 (구현 착수 전 확인)
1. **상세 = 별도 라우트 vs 케이스 카드 내 탭** — 인쇄/공유 고려 시 별도 라우트 제안(기본값으로 진행, 이견 시 회신)
2. **수정 반영 경로** — 의료진 오더 수정은 HIS에서 → ERP 재동기화(SoT=HIS) 전제. ERP 직접 수정 불가 원칙 확인(기본 가정)
3. **명세 시점 스냅샷** — interim(실시간) 기본. 청구확정 시점 스냅샷 보존(실삭감 후 비교용)은 P3 학습 단계로 미룸(기본 가정)
4. **위브병원 기관 종별** — 기관종별 본인부담률 설정에 필요(병원40%? 종합병원50%?) — P1 착수 시 1개 값 확인
