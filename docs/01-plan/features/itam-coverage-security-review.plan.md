## 2. 기능 완결성 판정 — 갭 매트릭스

### P0 (필수 — 핵심 운영 흐름 차단)

| # | 갭 | 판정 | 내용 |
|---|-----|------|------|
| **F-1** | **SW 서비스 수정 UI 전무** | 부분구현(API만) | `PATCH /itam/services/{id}`는 있으나 웹에 수정 폼 없음 → **구독 갱신 시 만기 연장·좌석 변경·해지통보일 수정이 화면에서 불가**(write-once). 갱신 관리가 SW 트랙의 존재 이유 |
| **F-2** | **서비스 해지/상태 필드 부재** | 미구현 | SoftwareService에 status(ACTIVE/CANCELLED) 없음 → 해지 구독이 목록·준수율·비용점검에 영구 잔존(expires_on 소급으로만 우회). 유령 구독 탐지 목적과 충돌 |

### P1 (권장 — 감사·비용통제·자산책임 공백)

| # | 갭 | 내용 |
|---|-----|------|
| F-3 | **도입/폐기 결재선 미연동** | 결재 doc_type에 ITAM 없음·itam 코드에 approval 참조 0건 — 폐기가 ADMIN 단독 실행. **릴리스 리포트 §4 "결재선 재사용" 표기는 과대**(가용 인프라이지 연동 아님) → 리포트 정정 필요 |
| F-4 | **자산 개별 편집 UI 부재** | PATCH EP는 전 필드 수용하나 상세 모달에 수정 폼 없음. bulk는 12열만 — **소유부서·MAC·보안등급·암호화/백신·UDI/허가·교정일·finance/계약 연결은 등록 후 수정 불가**, 소유부서는 등록폼에도 없음. 상태 변경(수리·대여·분실) 개별 버튼 없음 |
| F-5 | **감가상각 연계 UI 미노출** | finance_asset_id·intangible_asset_id 모델/API만 — 웹 사용 0건(기획 핵심 전제 미도달) |
| F-6 | **비용 트랙 후반 미착수** | 예산 대비·부서(cost_center) 배분·벤더별 집계·전표 연동·BI 마트 전부 없음(opex는 유형별만). cost_center는 저장만 되고 미사용 |
| F-7 | **수령확인 SELF 경로 부재** | acknowledge가 ADMIN write 전용 → 실수령자(직원)가 본인 확인 불가 — chain-of-custody가 대리확인으로 변질. 배정 개인 알림도 없음 |
| F-8 | **갱신 이력 미보존** | expires_on 덮어쓰기 + **SW update 감사에 before 부재**(ITAsset update는 before 기록·SW만 비대칭) → 이전 만기·단가가 감사에도 안 남음. 갱신 횟수·인상 추이 추적 불가 |
| F-9 | **실사 이력 미보존** | 위치 patch만 — last_audited_at·실사 세션(미확인 자산 리포트) 없음 → 전수 실사 입증 불가 |
| F-10 | **CSV/Excel 내보내기 없음** | 자산대장·비용 원장 다운로드 부재(감사 제출용) |

### 3.3 보안 성숙도 평가

1. **기반 통제 견고**: 전 EP RBAC 누락 0 · 전 변이 감사 · 라이선스 키 AES-GCM(AAD) · 첨부 화이트리스트 ·
   v1.41.0 가드 10건 실재 — 동급 사내 ITAM 대비 상위.
2. **주 리스크 = 경로 비대칭**: update에 걸어둔 가드가 create/bulk/플래그 변경 경로에서 우회되고,
   단일 write 스코프라 ADMIN 1인이 감사로그 외 저지선 없이 폐기·증빙 삭제까지 완결 가능(SoD 부재).
3. MED 5건을 닫으면 "우회 경로 없음 + SoD 백로그" 상태로 기재 가능.

## 5. 결정 필요

- **결재선 임계**: 자산 도입/폐기 승인 금액 기준(결재 룰) — 경영진 결정.
- **SoD 스코프 세분**(itam.dispose·itam.license 등) — 운영 인원 규모 고려.

- **비용 전표 연동 수위**(기획 §7 유보 지속) — 재무팀 협의.
