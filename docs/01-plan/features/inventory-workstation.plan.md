# 재고 워크스테이션 기획서 (바코드 입력·출력 + 현장 작업대)

> **요약**: 창고·물류 담당자가 **스캐너 우선(scanner-first)** 으로 입고·출고·실사·조회를 빠르게 처리하는
> **전용 작업대(워크스테이션)** 와, 품목·로트 **바코드 등록·라벨 출력**을 도입한다. 기존 관리 화면
> (`/inventory*`)은 마스터·분석용으로 유지하고, 워크스테이션은 **반복 현장 작업 전용**(큰 버튼·스캔 입력·
> 최소 내비)으로 분리한다.
> **작성일**: 2026-06-16 · **버전**: v0.1(기획·협의) · **상태**: 기획 · **우선순위**: High(현장 효율·오입력 감소)
> **연관**: scm(Item·Lot·StockMovement·PO·StockTake), FR-11/12/13/46(재고·FIFO·안전재고·마약류),
> 재고 화면 `/inventory`·`-valuation`·`-stocktake`·`-contracts`

---

## 1. 배경 / 문제

- 현재 재고 기능은 **관리자 관점 화면**(목록·발주보드·평가·실사)에 흩어져 있어, **창고 현장의 반복 작업**
  (수십 건 입고 검수, 출고, 실사 카운트)에는 클릭·검색이 많아 느리고 오입력 위험이 큼.
- **바코드 미지원**: Item에 `code`(내부코드)만 있고 **바코드 필드·GS1 로트 바코드·라벨 출력이 없음**.
  입고 시 품목·로트·유효기간을 수기 입력 → 오타·시간 소요. 마약류·유효기간 관리에 특히 취약.
- 결과: 현장은 종이/엑셀 병행, ERP 반영 지연·불일치 발생.

→ **스캔 한 번으로 품목·로트·유효기간을 인식**하고, **라벨을 출력**해 부착하면 현장 작업이 표준화·고속화된다.

---

## 2. 현황 자산 (재사용 기반)

| 자산 | 위치 | 워크스테이션 활용 |
|------|------|------------------|
| 품목 마스터 `Item`(code·unit·safety_stock) | scm.items | 바코드 등록 대상·스캔 조회 키 |
| 로트 `Lot`(lot_no·**expiry_on**·remaining·unit_cost) | scm.lots | 로트 바코드(GS1)·유효기간 인식 |
| 입출고 `StockService.receive/issue`(FIFO·음수방어) | stock_service | 스캔 입고/출고의 백엔드(그대로 호출) |
| 발주 `PoService.request/approve/receive` | po_service | 발주 기반 입고 검수 |
| 실사 `StockTakeService.record/apply` | stocktake_service | 스캔 실사 카운트 |
| 마약류 수불 `NarcoticsLedger`(append-only) | narcotics_service | 스캔 마약류 입출고 |
| 유효임박 `expiring_lots` | stock_service | 워크스테이션 경고 |

> **핵심**: 입출고·실사·발주 도메인 로직은 이미 있다. 워크스테이션은 **빠른 입력 UI + 바코드(필드·라벨)**
> 를 더하는 것이며, 신규 도메인이 아니다.

## 3. 갭 분석 (신규 필요)

| # | 갭 | 현 상태 | 비고 |
|---|----|--------|------|
| G-1 | **바코드 필드** | Item에 barcode 없음 | 품목 바코드(자체 또는 GTIN)·로트 바코드 |
| G-2 | **바코드 스캔 입력** | 없음 | USB/BT 스캐너(키보드 웨지) + 카메라 스캔(모바일) |

| G-4 | **전용 워크스테이션 UI** | 관리 화면만 | 입고/출고/실사/조회 모드·큰 버튼·스캔 포커스 |
| G-5 | 스캔→로트·유효기간 파싱 | 없음 | GS1-128 AI(01 GTIN·10 lot·17 expiry) 파서 |

## 4. 목표 / 범위

**목표**: 창고 담당자가 **스캔 중심으로 입고·출고·실사·조회를 1화면에서 고속 처리**하고, **품목·로트
라벨을 출력**해 현장 식별을 표준화한다.

**범위(1차)**: ① 바코드 필드(품목·로트) ② 스캔 입력(스캐너 키보드 웨지 우선) ③ 라벨 출력(품목·로트)
④ 워크스테이션 화면(입고·출고·실사·조회 모드). 백엔드는 기존 서비스 재사용.
**비범위(후순위)**: 카메라 스캔(모바일 PWA), GS1-128 완전 파싱, 라벨 프린터 직접 연동(ZPL), RFID(FR-44 별건).

## 5. 핵심 기능

### ① 바코드 데이터 (G-1, G-5)
- `Item.barcode`(품목 바코드 — 자체 발번 또는 제조사 GTIN, unique·nullable) 추가.
- **로트 바코드**: 출력 시 GS1-128 형식 권장 — `(01)GTIN(17)YYMMDD(10)LOT`. 스캔 시 파서가 GTIN·유효기간·
  로트를 분해해 자동 채움. GS1 미사용 시 자체 인코딩(예: `item_code|lot_no|expiry`) Code128/QR.
- 스캔 식별 우선순위: barcode → item.code → lot 바코드.

### ② 스캔 입력 (G-2)
- **스캐너(키보드 웨지) 우선**: 화면에 항상 포커스된 입력창이 스캔 문자열+Enter를 수신 → 즉시 품목/로트
  해소. 별도 드라이버 불필요(대부분 USB/BT 스캐너가 키 입력 방식).
- **카메라 스캔(후순위·옵트인)**: 모바일/태블릿에서 카메라로 스캔(JS 바코드 라이브러리). HTTPS 필요(프로드 충족).

### ③ 라벨 출력 (G-3)
- 품목 라벨: 품명·코드·바코드(Code128/QR). 로트 라벨: 품명·로트·유효기간·바코드(GS1-128 권장).
- **출력 방식(1차)**: 서버가 라벨 시트(HTML/PDF)를 생성 → 브라우저 인쇄(A4 다열 또는 라벨용지).
  바코드 렌더는 서버(예: python-barcode/qrcode) 또는 클라이언트 라이브러리.
- 후순위: 라벨 프린터(Zebra ZPL) 직접 전송.

### ④ 워크스테이션 화면 (G-4) — `/inventory/workstation`
스캐너 친화 단일 화면, 모드 전환(탭/큰 버튼):
- **입고**: (발주 선택 or 직접) 품목 스캔 → 로트·유효기간·수량 입력(로트 라벨 스캔 시 자동) → 입고 확정.
  발주 기반이면 검수 수량 대조. 입고 후 **로트 라벨 즉시 출력** 옵션.
- **출고**: 품목 스캔 → 수량 입력 → FIFO 출고(임박 로트 경고). 부서/용도 선택.
- **실사**: 품목/로트 스캔 → 실사 수량 입력 → 장부 대비 차이 즉시 표시 → 일괄 반영(기존 stocktake).
- **조회**: 스캔/검색으로 품목 재고·로트·유효임박·안전재고 미달을 즉시 표시.
- 마약류 품목은 스캔 시 **수불부 경로**로 분기(append-only·사유).
- UX: 큰 글씨·큰 버튼·최근 작업 로그·연속 스캔(핸즈프리)·오류 음/색 피드백.

## 6. 우선순위 / 로드맵

| 단계 | 내용 | 비고 |
|------|------|------|
| **M1** | 바코드 필드(Item.barcode, 마이그) + 품목 라벨 출력 + 워크스테이션 **조회/입고** 모드(스캐너 웨지) | 데이터·기존 서비스 자족 |
| **M2** | **출고/실사** 모드 + 로트 라벨(GS1-128) + 스캔 파서 | |
| **M3** | 마약류 스캔 분기 + 발주 검수 대조 강화 | |
| (후) | 카메라 스캔(모바일) · 라벨 프린터(ZPL) 직접 연동 | 외부/하드웨어 |

각 단계 기존 패턴(서비스 재사용·테스트·PR→배포). 신규 마이그는 Item.barcode·로트 라벨 메타 정도.

## 8. 평가지표 / 완료기준
- 입고/출고 1건 처리 시간 단축(클릭·검색 감소), 수기 오입력 감소.
- 라벨 출력→부착→스캔 인식 라운드트립 성공.
- 유효임박·안전재고 미달이 워크스테이션에서 즉시 가시화.
- 기존 재고 정합(FIFO·음수방어·마약류 수불) 무회귀.

## 9. 리스크 / 완화
| 리스크 | 완화 |
|--------|------|
| 스캐너 기종별 접미문자(Enter/Tab) 상이 | 입력창에서 Enter/Tab 모두 종료문자 처리·설정값 |
