# 회계 IFRS(K-IFRS) 정합 강화 기획서

> **요약**: [ifrs-conformance-analysis.md](../../03-analysis/ifrs-conformance-analysis.md)에서 식별한
> IFRS 갭(이연법인세·대손충당·재고저가법·보험수리퇴직급여·포괄손익/주석·발생주의수익·외화환산)을
> **기존 전표·계정·마감 인프라 위에서** 단계적으로 보완한다. 신규 도메인이 아니라 **기말 측정·결산조정·
> 표시 레이어** 추가가 핵심이다. 모든 조정은 **결산분개(전표)로 귀결**되어 기존 재무제표·감사추적과
> 자연 통합된다.
>
> **목표 부합도: 95%+** (현 ~65%). 측정엔진(P0~P1)으로 자산·세후손익을 IFRS 수준으로, 공시 완전체
> (P2)·정책/발생주의/기타(P3)로 표시·공시를 완성한다. 잔여 ~3~5%는 보험계리·세무조정·외부감사 서명 등
> **소프트웨어 외 전문가 영역**(상한 ~95~97%).
>
> **각 구현 단계는 코드와 함께 「인증·증빙 문서」를 동시 산출**한다(§9) — 회계정책서·측정방법론·통제기술서·
> 기준 준수 체크리스트·경영진 표명·테스트 증빙. 외부감사/내부회계관리제도(ICFR) 대응 자료로 누적된다.

## 1. 목표 / 비목표

**목표**
- IFRS의 **기말 측정·결산조정**을 ERP 내 계산 엔진으로 구현 → 외부 결산조정 의존 최소화.
- 모든 조정을 **결산분개(전표)** 로 산출 → 재무제표·감사추적·역분개 인프라 재사용.
- 결산 마감 사전점검(`period_service.preclose_check`)에 IFRS 조정 항목을 **체크리스트로 통합**.

**비목표**
- 외부감사·세무신고 자동제출(국세청 연동)은 범위 외(기초 데이터 산출까지).
- 정성 주석의 문구 자동작성이 아니라 **주석 데이터·골격 + 산출 가능 정량주석 자동화**(유형자산 증감표·
  충당부채 증감·리스 만기·부문·특수관계자 거래) 제공. 회계정책 등 정성 문구는 수기 편집.
- 의료기관회계기준 vs K-IFRS 강제 선택은 기관 결정 사항(본 기획은 K-IFRS 정합 옵션 제공).

## 2. 설계 원칙 (공통)

1. **조정=전표**: 모든 IFRS 조정은 `VoucherService.create`로 결산분개 생성(멱등 `source_ref`,
   `allow_closed`는 결산 전기 시에만). 별도 "그림자 장부" 금지.
2. **결산 시점 산출**: 월/연 마감 시 측정 엔진이 조정액 계산 → 미리보기(preview) → 확정(전기). 직접 잔액
   조작 없음.
3. **가정의 설정값화**: 할인율·임금상승률·대손율·법인세율 등은 하드코딩 금지 → 설정 테이블(감사·시점관리).
4. **계정과목 신설은 최소**: 신규 계정은 마이그레이션 시드(코드·kind·cost_type) + COA 화면 노출.
5. **경계 계약 준수**: 측정 엔진은 `finance` 도메인 내. analytics는 집계만(↛claims/tax 직접).
6. **테스트 우선**: 각 측정 엔진은 단위 테스트(경계·멱등·정합) 필수. ruff·import-linter·tsc 그린 유지.

## 4. 단계별 상세 설계

### P0-1. 대손충당금 / 기대신용손실 (K-IFRS 1109·1037)

- **목적**: 미수금을 회수가능액으로 평가 → 자산·손익 과대 해소.
- **기준 접근**: 단순화된 ECL(연령기반 충당률 매트릭스). aging 버킷별 충당률(current/1-30/31-60/61-90/90+)을
  설정값으로 두고 충당액 산출. (전면 forward-looking ECL은 후속.)
- **데이터 모델**: `finance.allowance_rates`(kind=AR, bucket, rate, valid_from) 신규 + 결산 시 `Receivable`
  잔액 aging × rate 합산.
- **로직**(신규 `AllowanceService`):
  1. `settlement_service.aging(kind=AR)` 재사용 → 버킷별 잔액.
  2. 목표 충당액 = Σ(bucket 잔액 × rate). 현재 충당잔액(1190)과 차액만 조정.
  3. 전입: `대손상각비 5660 / 대손충당금 1190`(증가), 환입은 반대. 멱등 `source_ref=allowance:AR:{yyyymm}`.
- **재무제표 반영**: BS 자산에 1190을 미수금 차감표시(`statements.balance_sheet` 차감계정 처리 추가).
- **엔드포인트**: `GET /finance/allowance/preview?yyyymm=`·`POST /finance/allowance/post`. 정책 `finance.closing`.
- **UI**: 결산 화면에 "대손충당 미리보기·전기" 패널 + 충당률 설정(`/finance-accounts` 인근 또는 설정).
- **테스트**: 버킷별 충당 계산·차액조정·멱등·환입.
- **한계**: 간이 매트릭스(거시지표 미반영) — 명시 표기.

### P0-2. 이연법인세 (K-IFRS 1012)

- **목적**: 회계이익과 과세소득의 **일시적차이**를 DTA/DTL로 인식 → 세후손익 정확화.
- **기준 접근**: 일시적차이 원천을 ERP가 아는 항목으로 한정(자동 식별):
  - 퇴직급여충당부채(2120) — 세무상 손금 시점 차이
  - 자산손상누계(1815)·재평가잉여금(3400)
  - 대손충당금(1190, P0-1)·재고평가충당금(1159, P0-3)
  - 감가상각 회계/세무 차이(내용연수 차이 — 세무 기준내용연수 설정 시)
- **데이터 모델**: `finance.tax_rate_settings`(corporate_tax_rate, valid_from), `finance.temp_differences`
  (period, source, book_value, tax_base, diff, dt_type) 스냅샷.
- **로직**(신규 `DeferredTaxService`):
  1. 각 원천의 장부가 vs 세무기준액 차이 집계 → 일시적차이.
  2. DTA/DTL = 차이 × 세율. 회수가능성(실현가능) 단순 가정(이월결손 별도).
  3. 전기: `이연법인세자산 1180 / 법인세비용 5810`(DTA 증가) 등. 당기법인세는 과세소득×세율 →
     `법인세비용 5810 / 미지급법인세 2230`.
  4. 멱등 `source_ref=deferred-tax:{year}`. 연 1회(또는 분기).
- **재무제표 반영**: IS에 법인세비용 표시 → 세후 당기순이익. BS에 DTA/DTL.
- **엔드포인트**: `GET /finance/deferred-tax/preview?year=`·`POST /finance/deferred-tax/post`.
- **테스트**: 일시적차이 집계·세율 적용·DTA/DTL 부호·멱등.
- **한계**: 이월결손공제·최저한세·세무조정 세부는 세무 자문 영역 — 기초 산출까지. **세무 전문 검증 권장** 표기.

### P0-3. 재고 저가법 / NRV (K-IFRS 1002)

- **목적**: 재고를 min(취득원가, 순실현가능가치)로 평가 → 진부·손상 재고 과대 해소.
- **데이터 모델**: `scm.items`(또는 lot)에 `nrv_unit`(순실현가능가치 단가) 입력 컬럼 + 결산 시 평가.
- **로직**(`valuation_service` 확장):
  1. 품목별 장부가(FIFO 잔량×원가) vs NRV(잔량×nrv_unit) 비교.
  2. 평가손실 = max(0, 장부가 − NRV) 합. 충당잔액(1159)과 차액 조정.
  3. 전입: `재고자산평가손실 5540 / 재고자산평가충당금 1159`. 회복 시 환입(취득원가 한도).
  4. 멱등 `source_ref=inventory-nrv:{yyyymm}`.
- **재무제표 반영**: BS 재고에 1159 차감표시.
- **원가흐름 옵션**: 현 FIFO에 더해 **가중평균(이동평균)** 선택 지원(품목 설정 `cost_method`). 산식
  분기 + 기존 FIFO와 동일 인터페이스. 표준원가는 범위 외.
- **엔드포인트**: `GET /finance/inventory-nrv/preview`·`POST /post`. NRV 입력은 재고평가 화면.
- **테스트**: 저가 판정·환입 한도·멱등·가중평균 단가.
- **한계**: NRV는 수기 입력(시장가 자동수집 없음) — 회전율 기반 자동 제안은 후속.

### P1-1. 퇴직급여 보험수리적 평가 (K-IFRS 1019)

- **목적**: 확정급여채무(DBO)를 **할인율·미래임금상승 반영 현가**로 측정.
- **데이터 모델**: `hr.actuarial_assumptions`(discount_rate, salary_growth, valid_from).
- **로직**(`retirement_service` 확장 — 간이 PUC 근사):
  1. 직원별 예상퇴직급여 = 현재 평균임금 × (1+임금상승)^잔여근속 × 근속연수환산.
  2. DBO = Σ 예상급여 현가(할인). 기존 명목 충당과 차액 = 재측정.
  3. 정상원가·이자원가는 PL(5320), 가정변경·경험차이 **재측정요소는 OCI(3410)** 로.
  4. 멱등 `source_ref=dbo-remeasure:{yyyymm}`.
- **재무제표 반영**: 충당부채(2120) 현가화, OCI(3410) 자본변동표·포괄손익 반영.
- **테스트**: 현가 계산·OCI 분리·차액조정.
- **한계**: 완전 보험수리(사망률·이직률 테이블)는 외부 평가 — 간이 모델 명시.

### P1-2. 포괄손익계산서 · OCI 표시 (K-IFRS 1001)

- **목적**: 손익을 **당기손익 + 기타포괄손익(OCI)** 2단 구조로 표시.
- **로직**(`statements.py` 확장): `income_statement`에 OCI 섹션 추가 — 재평가잉여금(3400) 증감,
  보험수리적손익(3410), 외화환산(해당 시) 당기 변동을 OCI로 집계. 총포괄손익 = 당기순이익 + OCI.
- **엔드포인트**: 기존 `/finance/income` 확장(oci 블록) 또는 `/finance/comprehensive-income`.
- **UI**: 재무제표 화면에 포괄손익 섹션.
- **테스트**: OCI 항목 집계·총포괄손익 정합.

### P1-3. 주석 공시 골격 (K-IFRS 1001)

- **목적**: 주요 주석 데이터·골격 제공(텍스트 자동생성 아님).
- **데이터 모델**: `finance.disclosure_notes`(period, note_key, title, payload JSON) — 회계정책·유형자산
  증감표·리스·충당부채 증감·특수관계자·우발부채 등 표준 note_key.
- **로직**: 마감 시 산출 가능한 주석(유형자산 증감표·충당부채 증감·리스 만기분석)은 기존 서비스에서
  자동 채움, 정성 주석(회계정책 등)은 수기 편집.
- **엔드포인트**: `GET/PUT /finance/disclosures?period=`.
- **UI**: 재무제표 화면 주석 탭.

### P1-4. 자산손상 환입 (K-IFRS 1036)

- **목적**: 손상 사유 소멸 시 손상차손 환입(원가모형 한도: 손상 안 했을 경우 장부가).
- **로직**(`asset_service` 확장): 회수가능액 회복 시 `손상누계 1815 / 손상차손환입(수익)` — 환입 한도 검증.
- **테스트**: 환입 한도 초과 차단·멱등.

### P1-5. 리스 정밀화 (K-IFRS 1116)

- **단기·소액리스 면제**: 계약 플래그(short_term/low_value) → 사용권자산 미인식, 비용 직접 처리(정액).
- **리스변경 재측정**: 지급액·기간 변경 시 리스부채 재측정·사용권자산 조정(`lease_service` 재측정 함수).
- **주석**: 리스부채 만기분석(IFRS 16 공시) → disclosure_notes(P1-3) note_key=lease.

### P2-1. 영업부문 보고 (K-IFRS 1108) — quick-win

- **목적**: 기존 진료과별 손익(`costing.department_pl`·`analytics`)을 **부문보고 형식**으로 정식화.
- **로직**: 부문(진료과/사업부) 단위 수익·손익·자산을 집계하는 `segment_report` — 기존 부서손익 재사용 +
  부문자산 매핑(자산 department_id). 보고부문 임계(10% 규칙) 적용 옵션.
- **엔드포인트**: `GET /finance/segments?period=`. **UI**: 재무제표 부문 탭(이미 진료과 손익 UI 재사용).
- **비고**: 측정 신규 없음 — 표시·임계 적용만. 부합도 quick-win.

### P2-2. 공시 패키지 (특수관계자·우발·후속사건·공정가치·중간보고·전기비교)

- **특수관계자(1024)**: `finance.related_parties`(party, relation) + 거래 태깅(전표 메모/플래그) → 거래·잔액 공시.
- **우발부채/우발자산(1037)**: `finance.contingencies`(type, description, estimate, likelihood) 등록·주석.
- **보고기간후사건(1010)**: 마감~공시 사이 사건 등록(수정/비수정 구분) → 수정사건은 결산분개 반영, 비수정은 주석.
- **공정가치 서열(1113)**: 재평가·금융자산에 측정수준(Level 1/2/3)·기법 메타 + 공시.
- **중간재무보고(1034)**: 월/분기 요약 재무제표(누적·비교) 형식 — 기존 월별 산출 재사용.
- **전기 비교표시(1001)**: 재무제표 산출에 당기/전기 2기 컬럼 표준화(`statements.py` 비교 파라미터).
- 모두 disclosure_notes(P1-3) 골격 위에 데이터 채움. 측정 신규 거의 없음(표시·등록·공시 중심).

### P3-1. 수익인식 발생주의 정합 (K-IFRS 1115) — 5단계

- **목적**: 수납(현금)시점 인식을 **수행의무·진행기준**으로 정합(특히 입원·검진권).
- **접근**: (a) 입원 진행기준 — 미청구수익(unbilled, 계약자산) 인식; (b) 검진권 선수금 시효 도래 시 수익
  인식; (c) 보험청구 결정 전 발생수익 추정.
- **데이터 의존**: 진료 진행률 데이터(HIS) — 일부 외부 의존. ERP 단독 가능분(검진권 시효·미청구 추정) 우선.
- **한계**: 진행률 기반 입원수익은 HIS 진행 데이터 필요 → 단계 분리.

### P3-2. 회계정책·추정변경·오류 (K-IFRS 1008)

- **목적**: 회계정책 변경(소급)·추정변경(전진)·오류수정(소급재작성) 절차·이력.
- **데이터 모델**: `finance.accounting_changes`(type, standard, description, effect, retrospective).
- **로직**: 소급 시 비교표시 재작성 플래그 + 이익잉여금 기초 조정 전표, 전진 시 당기 이후만. 오류수정은
  역분개 인프라 + 비교재작성 표기.
- **비고**: 비교표시(P2-2)·주석(P1-3)과 연계.

### P3-3. 외화 기말환산 (K-IFRS 1021)

- **목적**: 외화 화폐성 자산·부채를 기말환율로 환산 → 환산차손익 인식. (Stage2 연계 — 외화 voucher 라우팅.)
- **로직**: 외화계좌(corporate_accounts) 통화별 잔액 × 기말환율 − 장부가 = 환산차 → `외화환산이익 4620 /
  외화환산손실 5670`. 환율 소스 설정.
- **연관**: [erp-corporate-fx-accounts] Stage2.

### P3-4. 차입원가 자본화(1023)·무형자산(1038)

- **차입원가(1023)**: 적격자산 건설기간 차입원가 자본화(자산 원가 가산) — 건설중자산·차입 발생 시.
- **무형자산(1038)**: 무형자산(1850) 취득·상각(5215)·손상 — 정액 상각, 내용연수. 자체개발 자본화 조건.
- **비고**: 현재 거래 규모 확인 후 착수(조건부). 모듈 패턴은 유형자산(asset_service) 재사용.

## 5. 로드맵 / 부합도 단계표 (95%+ 경로)

각 단계 누적 시 부합도 추정:

| 단계 | 포함 항목 | 마이그 | 외부 의존 | 누적 부합도 |
|---|---|---|---|:---:|
| (현재) | 기록·정산·유형자산·리스·현금흐름·재평가 | — | — | **~65%** |
| **P0** | 대손충당(1109/1037)·이연법인세(1012)·재고저가법+가중평균(1002) | 1190/5660·세율/DTA1180/DTL2260/5810/2230·1159/5540·NRV | 세무자문·NRV입력 | **~80%** |
| **P1** | 퇴직보험수리+OCI(1019)·포괄손익(1001)·주석골격(1001)·손상환입(1036)·리스정밀화(1116) | 가정·3410·disclosure_notes | 가정승인 | **~88%** |
| **P2** | 영업부문(1108)·특수관계자(1024)·우발(1037)·후속사건(1010)·공정가치서열(1113)·중간보고(1034)·전기비교(1001) | related_parties·contingencies·메타 | 없음 | **~93%** |
| **P3** | 수익 발생주의 5단계(1115)·회계정책/추정변경/오류(1008)·외화환산(1021)·차입원가/무형(1023/1038) | unbilled1135/계약부채2145·accounting_changes·환율·1850/1855/5215 | HIS진행·환율 | **~96%** |
| (상한) | 보험계리 완전 DBO·세무조정·외부감사 서명 | — | 전문가 | **~97%(SW상한)** |

> 단계 내 각 항목은 **독립 PR + 결산 미리보기/전기 + 테스트 + 배포**. 결산 사전점검 체크리스트에 신규 조정 추가.
> P0~P1(측정)으로 자산·세후손익 정확도를, P2(공시)·P3(정책/발생주의)로 표시·공시를 완성 → **95%+ 달성**.
> P2는 측정 신규가 거의 없어(기존 자산 형식화·등록·공시) 빠르게 부합도를 끌어올리는 구간.

## 6. 결산 통합 (공통 귀결점)

- `period_service.preclose_check`에 신규 점검 추가: 대손충당 미전기·재고NRV 미평가·이연법인세 미계상·

  ④ 재고저가(1002) → ⑤ 외화환산(1021) → ⑥ 퇴직 재측정(1019, OCI) → ⑦ **이연법인세(1012, 타 조정 모두 반영 후)**
  → ⑧ 손익→이익잉여금 대체. (이연법인세는 모든 일시적차이 확정 후 마지막 측정.)
- 모든 조정 전표는 `source_module="closing-ifrs"` 네임스페이스로 식별·역분개 가능.
- 공시(P2)·정책변경(P3)은 마감 후 **공시 단계**에서 disclosure_notes·비교표시에 반영.

## 9. 인증·증빙 문서 트랙 (외부감사·ICFR 대응)

> 전제: IFRS는 별도 "인증서"가 발급되는 제도가 아니라 **외부감사인의 감사의견**으로 적정성이 표명되고,
> 상장·대형 법인은 **내부회계관리제도(ICFR)** 운영실태를 평가받는다. 따라서 본 트랙은 *감사·평가에
> 제출 가능한 증빙 패키지*를 코드와 함께 누적 생성한다(자체 발급 "인증서"가 아님).

### 9.1 인증 기준(준거) 프레임워크
- **회계기준**: K-IFRS(기업회계기준서) 각 호 + (의료법인) 의료기관 회계기준 규칙 병행.
- **감사기준**: 회계감사기준(K-ISA) — 감사인이 재무제표를 감사. ERP는 **감사증거(audit evidence)** 제공.
- **내부통제**: 내부회계관리제도(ICFR, K-SOX) — 재무보고 통제. ERP는 통제활동(전표승인 SoD·기간잠금·
  감사로그·결산 체크리스트)을 **통제기술서·운영증빙**으로 문서화.
- **경영진 책임**: 경영진의 재무제표 작성책임·표명(management representation).

### 9.2 항목별 5종 문서 세트 (구현과 1:1)
각 P-항목 구현 시 다음을 동시 작성(`docs/06-compliance/ifrs/` 하위):

| 문서 | 내용 | 산출 |
|---|---|---|
| ① 회계정책서(policy) | 해당 기준의 인식·측정·표시 정책(예: 대손=연령기반 ECL 매트릭스) | 수기 + 설정값 인용 |
| ② 측정방법론서(methodology) | 산식·가정(할인율·세율·충당률)·데이터원천·예시계산 | 수기 + 코드 file:line |
| ③ 통제기술서(control) | 통제활동(승인·멱등·기간잠금·체크리스트)·통제주체·주기·증적 | 수기 + 감사로그 참조 |
| ④ 준수 체크리스트(checklist) | 기준서 요구 인식·측정·공시 항목 vs 구현 매핑(충족/예외) | 표 |
| ⑤ 테스트·운영 증빙(evidence) | 단위테스트 결과·결산 전/후 전표·재무제표 스냅샷·재현절차 | 자동(테스트) + 캡처 |

### 9.4 운영 원칙
- **추적성**: 모든 측정방법론서는 구현 file:line·마이그·테스트명을 인용(코드↔문서 양방향 추적).
- **시점·버전**: 가정(할인율·세율·충당률) 변경은 설정 시점관리 + 문서 개정이력.
- **상태대장**: `status-register.md`에 기준별 5종 문서 진행(작성/검토/승인)·부합도 기여를 기록.
- **감사 재현**: 증빙은 "결산 미리보기→전기→재무제표 반영" 재현 절차를 포함(감사인 검증 가능).
