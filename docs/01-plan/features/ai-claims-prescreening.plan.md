# AI 기반 사전심사·삭감 예방 기획서 (공시 연계)

> **요약**: 이미 example.org AI에 색인 중인 **공시(고시·심사기준)** 와 **삭감 이력**을 토대로, 청구 전
> **AI 사전심사**(삭감 위험 예측 + 근거 공시 인용)와 **삭감 사유 자동 귀속**을 도입한다. 결정론 룰엔진
> (FR-41)을 AI(RAG)로 증강하되 **휴먼인더루프**를 유지한다.
> **작성일**: 2026-06-09 · **버전 v1.1**(검토 보완) · **상태**: 기획(협의) · **우선순위**: High(삭감=직접
> 손실) · **연관**: FR-41 사전심사 룰엔진, FR-52/53 AI 색인 발신, claims 삭감/이의신청

> **v1.1 검토 보완 요약**: ① 전제조건(실 데이터·weve 역량·보안정책)을 **선결 게이트**로 명시(§1.5) —
> P0를 "바로 착수"로 본 것은 낙관. ② **섀도 모드·백테스팅** 검증 방법론 추가(§9.5). ③ AI 의료 SW
> 규제 분류·가명처리 기준 추가(§8). ④ 피드백 루프·드리프트 운영 추가(§10.5). ⑤ ROI 정량 프레임(§10).

## 1. 배경 / 문제

- **삭감은 즉각적 손실**: 청구 후 심평원 삭감 → 수익 차감 + 이의신청 행정비용. 사후 대응(이의신청)은
  성공률·회수율 한계.
- **룰엔진(FR-41)의 한계**: 현재 사전심사는 **명시 룰**(중복·산정횟수·미등재·금액이상)만. 그러나 실제
  삭감 사유의 다수는 **고시·심사지침의 자연어 기준**(적응증·산정요건·동시산정 제한·의학적 타당성)에서
  비롯 — 모든 경우를 룰로 코드화 불가, **매년 고시 개정**으로 유지보수 폭증.
- **이미 가진 것**: 공시(고시·**심사기준 REVIEW_CRITERIA**)가 **temporal 본문**으로 ERP에 적재되고
  **example.org AI에 색인 발신**(FR-52/53) 중. 삭감 이력(`claims.claim_adjustments`)이 **정답 데이터**로 축적.

→ **방대한 자연어 고시 + 삭감 이력을 AI가 해석·적용**하면, 룰로 못 잡는 삭감을 청구 전에 예방할 수 있다.

## 2.5 전제조건 — 선결 게이트 (검토 보완 ★)

> 본 기획의 **암묵적 가정 3가지가 실제로는 선결 과제**다. 충족 전 P1 이상 착수 불가 — 솔직히 명시.

| # | 전제 | 현재 실태 | 선결 |
|---|------|----------|------|
| **PR-1** | example.org가 **RAG 질의·LLM 평가** 제공 | 현재는 **색인 발신(FR-52/53)만** — 검색/평가 API 미확인 | weve 팀에 질의·평가 역량/API 확인. 없으면 **온프레 RAG**(임베딩DB+LLM) 구축 필요 |
| **PR-2** | **실 공시(고시·심사기준)** 적재 | 현재 데모 공시 3건만(`Notice`). 실 고시 본문 대량 적재 안 됨 | 보건복지부/심평원 고시·심사지침 **본문 수집·정규화·등록**(REVIEW_CRITERIA) |
| **PR-3** | **실 삭감 통보서**(정답 데이터) | **G1(MEDRLT 파서) 미해소** — 통보서 자동 파싱 미완, 삭감 이력 데모뿐 | 실 통보서 샘플 확보·파싱(기존 G1 게이트) → `claim_adjustments` 축적 |
| PR-4 | 환자정보 외부 LLM 전송 가능? | 격리망·개보법 | 보안 정책 확정(§8) — 불가 시 온프레 LLM |

→ **결론**: P0(공시 RAG 검색 PoC)는 PR-1·PR-2 일부만으로 가능하나, **삭감 예방의 실효(P1+)는 PR-3
(실 삭감 정답)에 의존**. 데이터 없이는 AI 적중률 검증 불가. 본 기획은 **PR-1~3 선결과 병행**해야 한다.

## 3. 목표 / 범위

**목표**: 청구 전 AI가 (1) 삭감 위험을 예측하고 (2) **근거 공시/고시 조항을 인용**하며 (3) 수정 권고를
제시 → **삭감률 감소**.

**범위(1차)**: 외래 행위별수가 청구 라인 대상. **AI는 보조(WARN·근거 제시)**, 차단은 결정론 룰 + 사람.
**비범위**: AI의 자동 청구 수정·자동 제출(휴먼인더루프 필수).

## 4. AI 아키텍처 (RAG — Retrieval-Augmented Generation)

```
[지식베이스] 공시·고시·심사기준(REVIEW_CRITERIA) + 삭감사례
      │ (이미 example.org 색인 — FR-52/53)
      ▼
[질의] 청구 라인(코드·상병·횟수·금액·진료일, 비식별)
      │  → 진료일 시점 유효 공시 검색(temporal) + 유사 삭감사례 검색
      ▼
[LLM 평가] "이 청구가 삭감될 위험은? 근거 고시 조항은? 수정 권고는?"
      │  → 반드시 **근거 인용**(공시 id·조항) 강제 — 인용 없으면 '판단보류'
      ▼
[출력] { 삭감위험: HIGH/MID/LOW, 사유, 근거공시[ {notice_id, 조항, 발췌} ], 권고, 신뢰도 }
      ▼
[사전심사 통합] 룰엔진 결과(BLOCK) + AI 결과(WARN·근거) → 사용자 검토 → 청구 결정
```

- **RAG 우선(파인튜닝 아님)**: 고시는 매년 변경 → 색인 갱신만으로 최신성 확보(재학습 불필요).
- **temporal 검색**: 청구 진료일에 유효한 공시(effective_from/to)만 근거로 — 과거건은 당시 기준.
- **환각 방지**: 출력에 **근거 공시 인용 필수**(notice_id + 발췌). 인용 불가 시 'AI 판단 보류'(룰엔진 결과만).

## 5. 핵심 기능 (4종)

### ① AI 사전심사 (룰 + AI 하이브리드)
- 청구 라인 → 룰엔진(결정론) + AI(RAG) 동시 평가.
- 룰 = BLOCK/WARN(명시), AI = WARN + **근거 공시 + 권고**(자연어 기준).
- 화면: 기존 `/claims/pre-review`에 **AI 소견·근거 공시 링크** 컬럼 추가.

### ② 삭감 사유 자동 귀속 (통보서 → 근거 공시)
- 심사결과통보서 삭감(`claim_adjustments`) 수신 시, AI가 **삭감 사유 ↔ 근거 고시/심사기준 자동 매칭**
  (`map_status` AUTO 자동화율 향상) + 유사 사례 클러스터링.
- 효과: 이의신청 근거 자동 수집, 재발 방지 룰/교육 도출.

### ③ 공시 변경 영향 분석
- 고시·심사기준 공시 **개정 등록 시**, AI가 **영향받는 청구 패턴·기존 룰**을 식별 → 담당자 알림
  (`notifications` APPROVAL/REGULATORY). 룰엔진에 신규 룰 후보 제안.

### ④ 삭감 예측·추세 (이력 학습)
- 진료과·코드별 삭감 위험 스코어·추세 → 경영분석(BI)·원가(삭감손실)와 연계. 고위험 패턴 사전 경고.

## 7. 룰엔진(FR-41)과의 관계

- **결정론 룰 = 1차 게이트**(중복·미등재 등 확실 건 BLOCK). **AI = 2차 보조**(자연어 기준 WARN·근거).
- AI 제안 룰은 **사람이 검증 후** PreReviewRule에 등재(엔진 무수정 확장 — 기존 설계 유지).
- **휴먼인더루프**: AI는 결정하지 않음. 최종 청구 결정은 담당자.

## 8. 보안 / 규제 (필수)

- **환자 비식별**: 질의에 차트번호·성명 등 식별자 제외(코드·상병·횟수·금액·진료일만). 기존 **민감정보
  필터 게이트(FR-53)** 재사용.
- **외부 전송 정책**: 환자정보 외부 LLM 전송 금지 시 → **온프레 LLM** 또는 비식별 통계만 전송. 격리망 전제.
- **설명가능성·감사**: 모든 AI 소견에 **근거 공시 인용 + 입력 스냅샷** 보존(`access_log`/전용 테이블).
  의료기관 책임상 "AI가 그랬다"는 불가 — 근거·사람 검토 기록 필수.
- **고시 최신성**: temporal 검색으로 진료일 기준 유효 공시만. 색인 지연 모니터.

### 8.5 규제 분류·가명처리 (검토 보완 ★)
- **의료기기 SW 해당 여부**: 본 AI는 **진료/진단이 아니라 청구 행정(삭감 예방) 보조** → 의료기기(SaMD)
  비해당 가능성이 높으나, "의학적 타당성" 판단 요소가 들어가면 경계. **식약처 SaMD 가이드 사전 검토**
  필수. 안전책: 출력은 **행정적 권고(근거 공시 제시)**에 한정, 임상 판단 미수행 명시.
- **개인정보(개보법)**: 청구건 평가는 가명·비식별로. 차트번호·성명 제외, **상병코드도 희귀상병은 재식별
  위험** → 통계화/범주화. 가명처리 적정성 평가·DPIA(영향평가) 권장.
- **표시 의무**: AI 소견에 "법적 효력 없음·심평원 심사와 무관·담당자 검토 필수" 명시.

| **P2** | **삭감 자동 귀속**(②) — 통보서 삭감↔공시 매칭, 자동화율↑ | map_status AUTO율 |
| **P3** | **공시 변경 영향 분석**(③) + **삭감 예측/추세**(④) | 알림 정확도·예측 재현율 |

> 각 단계는 비식별·근거인용·휴먼인더루프 원칙 유지. **P0.5 섀도 모드가 핵심 안전장치** — 사람에게
> 보여주기 전에 실 삭감과 대조해 신뢰도를 확보한 뒤 노출(잘못된 WARN으로 정당청구 누락 방지).

### 9.5 검증 방법론 (검토 보완 ★)
- **백테스팅**: 과거 삭감 통보서(정답)로 "AI가 그 건을 사전 WARN했는가" 측정 → **precision/recall** 산출.
  목표 임계(예: recall ≥ 0.7 & precision ≥ 0.5) 미달 시 노출 보류.
- **골든셋**: 의료보험팀 검수한 삭감/정상 표본 N건 — 회귀 평가 고정셋.
- **섀도→점진 노출**: 섀도(비노출)→고위험군만 노출→전체. A/B로 삭감률 변화 측정.
- **근거 검증**: AI가 인용한 공시가 실제 삭감 사유와 일치하는지 사람 표본 검수(환각 모니터).

## 10. 평가지표

- **삭감률**(청구 대비 삭감액) 감소 — 핵심 ROI
- AI 사전심사 **적중률/재현율**(삭감된 건을 사전에 WARN했는가)
- **근거 정확도**(인용 공시가 실제 삭감 사유와 일치)
- 삭감 자동귀속 **AUTO율**, 이의신청 인용률 변화

**ROI 정량 프레임(검토 보완)**: `절감액 = (도입前 삭감률 − 도입後 삭감률) × 월 청구액 × 사전수정율`.
선행: **현 삭감률 베이스라인 측정**(costing 삭감손실 활용) → 목표(예: 삭감률 −20%) → AI 비용(API/온프레
GPU·운영)과 대비. 베이스라인 없이 효과 주장 불가 → P0에서 베이스라인부터.

### 10.5 운영·피드백 루프 (검토 보완 ★)
- **휴먼 피드백 수집**: 담당자가 AI 소견에 "맞음/틀림/무관" 표시 → 오판 사례 축적(룰 후보·프롬프트 개선·
  골든셋 보강). UI에 피드백 버튼.
- **드리프트 모니터**: 고시 개정·색인 지연·삭감 패턴 변화 → 적중률 추이 대시보드. 임계 하락 시 알림.
- **장애 fallback**: AI 미응답/타임아웃 시 **룰엔진 결과만으로 즉시 반환**(AI는 보강 표시, 사전심사 자체는
  AI 의존 안 함). pre_review는 동기·즉시, AI 호출은 비동기·캐시.
