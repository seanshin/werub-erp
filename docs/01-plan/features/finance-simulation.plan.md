# Plan — 재무 미래 시뮬레이션 (finance-simulation)

> **배경**: 경영진 대시보드가 과거/현재 재무(손익·재무상태·재무비율·고정/변동비·현금흐름·
> 진료과 손익·이직률)를 드릴다운까지 제공하게 됐다(#331~#354). 다음 단계로, **가정(드라이버)을
> 바꿔 향후 재무를 예측·비교**하는 미래 시뮬레이션이 필요하다. 이미 갖춘 데이터·엔드포인트를
> 재사용해 baseline을 만들고, 가정 적용은 인터랙티브하게 처리한다.
>
> **레벨**: Enterprise | **상태**: 기획 v0.2 (2026-06-21, 검토 보완) | **승인 대기**
>
> **v0.2 보완(검토 반영)**: 손익 투영 공식·발생주의↔현금주의 조정·법인세 반영·민감도(토네이도)
> 분석·백테스트 검증·시나리오 데이터 스키마·계절성 한계 명시 추가.

## 1. 사용자와 문제

| 페르소나 | 현재 불편 | 목표 |
|----------|----------|------|
| 원장/이사 | 과거 숫자만 봄, "내년/투자 시 어떻게 되나" 답 없음 | 가정별 향후 손익·현금·비율 예측 |
| 행정원장(관리자) | 채용·수가인상·장비투자 영향 직관 불가 | 드라이버 슬라이더로 즉시 what-if |
| 재무 담당 | 자금 부족 시점·손익분기 수기 계산 | 현금 예측·BEP·안전한계율 자동 |

## 2. 핵심 기능

1. **손익 예측(P&L projection)** — 향후 12개월 월별 수익·고정비·변동비·순이익·이익률.
2. **현금흐름 예측(시나리오)** — 기존 `cash-forecast`에 가정 적용 → 월별 잔액·**자금 부족 시점·최저잔액**.
3. **손익분기(BEP)** — `BEP매출 = 고정비 / (1 − 변동비율)`, **안전한계율 = (매출−BEP)/매출**.
4. **시나리오 비교** — 기준(현추세)·낙관·비관 동시 비교·저장.
5. **목표 역산(goal-seek)** — 목표 순이익 달성에 필요한 매출/환자수/원가절감 역산.
6. **민감도(토네이도) 분석** — 각 드라이버 ±10% 변동 시 순이익 영향폭 → 핵심 변수 식별.

## 3. 입력 드라이버(가정)

| 분류 | 드라이버 | 기본값(baseline) |
|---|---|---|
| 수익 | 월 성장률 %(또는 환자수·수가 변동), 수가 인상 | 최근 추세 기울기 |
| 인건비 | 채용 N명·임금인상 %·이직 반영 | 현 월인건비·이직률 |
| 변동비 | 변동비율(재료비율) 조정 | 현 변동비율 |
| 고정비 | 고정비 증감(신규 장비 감가·임차) | 현 고정비 |
| 일회성 | 투자(자산취득)·차입(부채↑·현금↑) | 0 |
| 현금 | 수금/지급 회수기간(AR/AP) | 현 AR/AP 만기 |

## 4. 산출(예측)

- 월별 손익 추세 차트(기준 vs 시나리오) + 순이익·이익률 KPI
- 현금 잔액 추이 + 부족 경고(최저잔액 음수 시점)
- BEP 매출·안전한계율 게이지
- 부채비율·자기자본비율 추정 추이(일회성·이익 누적 반영)

## 4.1 투영 공식 (검토 보완 — 회계 정합)

**월별 손익(발생주의)** — 변동비는 매출 연동, 고정비는 독립:
```
수익_m   = 수익_(m-1) × (1 + 월성장률)            # 또는 환자수×평균단가
변동비_m = 수익_m × 변동비율(가정)                 # 매출 비례
고정비_m = 고정비_base × (1 + 고정비증감)
            + 신규채용Δ인건비 + 임금인상Δ − 이직Δ   # 인건비는 고정비에 포함
기타비용_m = 기타비용_base (비분류·영업외, 평탄 가정)
영업이익_m = 수익_m − 변동비_m − 고정비_m − 기타비용_m
법인세_m  = max(0, 영업이익_m) × 실효세율           # 의료법인 세율(가정, 기본 0 옵션)
순이익_m  = 영업이익_m − 법인세_m
```

**현금흐름(현금주의) — 발생↔현금 조정**:
```
영업현금_m = 순이익_m + 감가상각_m(비현금 환원)
            − ΔAR(수금지연) + ΔAP(지급지연)         # 운전자본 변화
투자현금_m = − 자산취득(일회성)
재무현금_m = + 차입 − 상환 − 배당
월말잔액_m = 월말잔액_(m-1) + 영업+투자+재무
```
→ **자금 부족 시점** = 월말잔액 최초 음수 월.

**손익분기(BEP)**: `BEP매출 = (고정비+기타고정) / (1 − 변동비율)`,
`안전한계율 = (예상매출 − BEP) / 예상매출`.

> 핵심: 순이익(발생) ≠ 현금. 감가상각 가산·투자/차입/운전자본을 분리 처리해야 현금예측이 타당.
> 법인세는 기본 0(세전)로 두고 실효세율 입력 시 세후 전환(옵션).

## 5. 아키텍처 (권장)

- **백엔드 `GET /analytics/sim-baseline?yyyymm=`**: 기준선 산출 — 월평균/추세 수익·고정비·변동비율·
  현재 현금·AR·AP·부채·자본. (기존 `trend`·`executive`·`cash-forecast`·`financial-ratios` 재사용,
  신규 집계 최소화). 권한 `analytics.reports` read(DIR/ADMIN). **마이그 불요.**
- **프론트 실시간 계산**: 드라이버 → baseline에 가정 적용해 **즉시 what-if** 투영(서버 왕복 없는
  순수 계산). Recharts 추세·게이지. 편집기/드릴 패턴(executive) 재사용.
- **시나리오 저장**: localStorage(편집기 패턴) → Phase 3에서 서버 영속 옵션.
- 화면 `/finance-simulation` (재무 메뉴, DIR/ADMIN). 경영진 대시보드에서 진입 링크.

**시나리오 데이터 스키마** (localStorage `fin-sim-scenarios-v1`, Phase 3 = `finance.sim_scenarios` 테이블):
```jsonc
{ "id": "uuid", "name": "낙관", "created_at": "...",
  "drivers": { "rev_growth": 0.02, "var_ratio": 0.18, "fixed_delta": 0.0,
               "hires": 3, "wage_raise": 0.03, "capex": 0, "loan": 0,
               "tax_rate": 0.0, "ar_days": 45, "ap_days": 30 } }
```
> 시뮬레이션은 **읽기 전용**(전표 미생성). baseline만 서버 권한 경유, 계산·시나리오는 클라.

> 계산을 클라이언트에 두는 이유: 슬라이더 조정마다 즉시 반응(인터랙티브) + 백엔드 부하 0.
> baseline만 서버가 제공(권한·데이터 SoT 유지).

## 6. 단계 (Phasing)

- **Phase 1 (MVP)**: `sim-baseline` 엔드포인트 + 손익 12개월 예측(성장률·인건비·변동비율 슬라이더)
  + BEP·안전한계율 + 기준/시나리오 차트 + **법인세율(옵션, 기본 0)**. (web + 백엔드 baseline, 마이그 무)
- **Phase 2**: 현금흐름 시나리오(감가 가산·운전자본·일회성 투자/차입) · 재무비율 추정 추이 ·
  **민감도(토네이도) 분석** · **백테스트 신뢰도 표시**.
- **Phase 3**: 목표 역산(goal-seek) · 계절성(YoY 가중) · 진료과별 시뮬 · 시나리오 서버 저장
  (`finance.sim_scenarios`) · PDF/엑셀 내보내기.

## 7. 비범위 / 가정

- 정밀 예측 모델(ML)·외부 거시지표 연동은 비범위 — **결정론적 가정 기반** 투영.
- baseline은 최근 N개월(기본 6) 추세에서 도출; 데이터 적은 월은 보수적 평탄화(중앙값·이상치 제외).
- **계절성 미반영(MVP)**: 단순 성장률 모델이라 독감철 등 월별 계절 패턴 미반영 — Phase 3에서
  최근 동월(YoY) 가중 계절지수 옵션. baseline 편차 큰 경우 화면에 "추세 신뢰도 낮음" 표시.
- 환자수→수익 환산은 단가 가정(현 평균) 사용; 진료과별 정밀 분해는 Phase 3.
- 다년(>12개월)·인플레이션·외화(외화계좌) 영향은 비범위(Phase 3 후보).

## 8. 데이터·재사용 (신규 의존성 0)

- 계정 원가구분(cost_type): 계정과목 관리(#343)

## 9. 성공 기준

- 드라이버 조정 시 손익·현금·BEP가 즉시(<100ms) 갱신.
- 기준 시나리오가 최근 실적 추세와 정합(검증).
- 자금 부족 시점·BEP가 회계적으로 타당(고정/변동 분류 기반).
- **백테스트**: 과거 시점(예: 6개월 전) baseline으로 예측한 값 vs 실제 실적 오차 ≤ 합의 임계
  (예: 순이익 ±15%) — 모델 신뢰도 검증. 화면에 baseline 신뢰 표시.
- 현금예측이 감가 가산·운전자본·투자/차입을 반영(순이익과 분리)해 발생↔현금 정합.
