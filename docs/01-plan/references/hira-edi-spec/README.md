## 핵심 발견

심사결과통보서는 **EDIFACT 계열 전문**이다 — `MEDRLT` 메시지:
- HEADER SECTION (UNH·BGM·DTM·NAD·CCI·RFF·AGR·FTX)
- BODY SECTION — Segment Group 구조:
  - **SG1 (M, ×150)**: 접수 단위 — DTM·RFF·MOA·CCI
  - **SG3 (C, ×99999)**: **명세서(명일련) 단위** — NAD·**ALC(조정)**·RFF·FTX·CCI·**MOA(금액 ×50)**·QTY·DTM
  - SG4~5: 라인(LIN) 단위 — 조정 항목별 금액·단가·수량
  - SG6~21: 지급불능·정산·추가 분류 그룹
- SUMMARY SECTION (AUT 인증·UNT)

→ **설계 매핑 확인**: `claim_batches`(접수)=SG1, `claim_statements`(명일련)=SG3, `claim_adjustments`(조정)=SG3-ALC/SG4-LIN — 기존 DDL과 정합. 세그먼트별 데이터 엘리먼트 상세(자릿수·코드값)는 ppt 구조도 참조.

## 검증 기록 (2026-06-21)

웹 + 저장소 자료 교차 확인으로 G1 잔여를 재평가:

- **① 공고 최신성 — 해소**: 출처 게시글(`brdBltNo=8690`)은 여전히 **공고 제2021-55호(2021-03-08)**, 별표1 zip 동일. 2021-55 이후 별표1(전자문서 EDIFACT 규격) **재공고 없음**. 갱신된 것은 *요양급여비용 청구방법·작성요령*(2023.7판·2024.7판)뿐 — 이는 명세서 서식 기재방법이며 전자문서 세그먼트/한정자 구조와는 별개. (2025-223호 별표1 미포함도 기확인) → **저장소 별표1 규격은 현행.**
- **② 구조 대조 — 정합 확인**: `26통보서_구조도_텍스트추출`·`25요양급여비용심사결과통보서1`(세그먼트 branching diagram)이 파서 세그먼트/필드 매핑과 일치 — SG1(접수)·SG3(명세서 일련번호)·SG4~5(줄/조정)·MOA 금액군(요양급여비용총액·심사결정액·본인일부부담금)·DTM(통보일자·요양개시일). `medrlt_parser.py`/`medrlt_qualifiers.py`의 의미 매핑 타당.
- **③ 한정자 코드값 — 미해소(자료 한계)**: 별표1(구조도·세그먼트 테이블)은 세그먼트·필드 *의미*만 수록, **RFF/MOA/FTX/DTM 한정자 코드값(ACE·AFA·79·52·129·137·194 등)은 부재**. 코드값은 별표1이 아니라 **전자문서 작성요령(별첨1)** 또는 실물 전문에서만 확정 가능 → `medrlt_qualifiers.py`는 **여전히 잠정값**, `medrlt_live_enabled=False` 유지 타당.

**결론**: G1 잔여 = ②**실물 2건**(운영 채널 의존) + ③**한정자 코드값**(작성요령 별첨1 확보 시 일부 선해소 가능). ①은 종결. 실물 도착 전 코드 변경 불요.
