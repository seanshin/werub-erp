> 출처: 사용자 제공 개발가이드 TOC (ef.hira.or.kr — 로그인 영역) +
> 공개 ebook 「심사평가정보 표준서식」 230p (G000CHG-2021-71, 공고 제2020-236호 기반)

## 정체 — 통보서 "수신"이 아닌 심사자료 "제출" 채널

| 채널 | 방향 | 형식 | 용도 |
|------|------|------|------|
| 청구포털 (DDMD) | 수신 | SAM/전문 (`C:\hira\DDMD\sam\out`) | 심사결과통보서 ← **G1 대상** |
| **HIRA e-Form** | 제출 | **JSON** (Agent/Broker 경유) | 심사자료·보완자료·이의신청 증빙 등 |
| HIRA e-Image | 제출 | DICOM | 의료영상 (SOPInstanceUID 등 5속성 필수) |

## e-Form JSON 데이터 구조 (별표 2 원문 — ebook p.15)

```json
{
  "metadata": { ... },          // 서식 공통 정보
  "elements": { ...,            // 서식별 일반 항목 (1항목 1값)
    "APND_DATA_NO": [{ ... }]   // 첨부파일 항목
  },
  "tables": { "KEY": [{...}, {...}] }  // 반복 표 항목
}
```
- 제출은 전용 **HIRA e-Form Agent** (JSON 변환·검증·송수신 API 프로그램) 경유
- 개발가이드 구성(사용자 제공 TOC): Agent 설치 / **Broker 구성·운영** / 인터페이스 정의 /
  심사평가정보 제출 API / 진료의뢰·회송 API 등 19장

## 표준서식 (제2부 — 40여 종 Layout 수록)

퇴원요약·진단/영상/병리검사결과지·수술기록·응급기록·입퇴원기록·간호기록·의사지시·임상관찰·투석기록 등 — 음영 항목 = 필수(E).

## ERP 반영 방침

- **Phase 1 영향 없음** — 통보서 수신(G1)과 별개 채널
- **Phase 2 후보 (FR-40 연계 강화)**: 이의신청·보완 시 증빙 의무기록을 e-Form Agent로
  제출하는 어댑터 — HIS가 e-Form Agent를 이미 쓰고 있는지 M0a에서 함께 확인 (병원이
  Agent 운영 중이면 ERP는 제출 트리거·상태 추적만)
- 개발가이드 §7(인터페이스 정의)·§8(제출 API)은 로그인 영역 — 병원 e-Form 계정으로
  접근 가능 (전산실 요청 시 첨부)
