# 심평원 심사결과통보서 수신 체계 조사 자료 (M0c 사전 조사)

> **Status**: 공개 자료 기반 조사 (2026-06-07) — **실물 전자파일 샘플·조정사유코드 전체 목록은 미확보, 요양기관업무포털에서 확보 필요**
> **Purpose**: Claims 모듈(FR-38~40) 설계의 사전 참고 자료. 본 자료만으로 매핑 구현 착수 금지 (enterprise-expert 권고 유지)

---

## ⚠️ 1. 핵심 발견 — "EDI"는 종료됨, 청구포털로 일원화

| 항목 | 내용 |
|------|------|
| 기존 KT EDI(VAN) 서비스 | 1996년 도입 → **2025년 3월 말 종료** |
| 현행 채널 | **심평원 청구포털시스템** (biz.hira.or.kr, 2011년 자체 개발, 무료) — 2026년 4월부터 완전 일원화 |
| 이용률 | 청구포털 98.7% (2025년 기준) |

**설계 영향 (중요)**:
- PRD 1.2의 "심평원에서 수신되는 EDI 전자문서"는 실무상 **청구포털을 통한 전자문서 송수신**을 의미함
- 통보서 수신 주체는 일반적으로 **청구 소프트웨어(HIS 청구 모듈) 또는 청구포털 프로그램** — ERP가 심평원과 직접 통신하는 구조가 아닐 가능성이 높음
- ERP의 현실적 수신 경로 (설계 시 택1 또는 병행):
  1. **HIS 청구 모듈이 수신한 통보 파일 폴더/DB 연계** (ERP가 HIS 서버에 동거하므로 유력)
  2. 청구포털에서 수동 다운로드한 파일을 ERP에 업로드 (fallback)
  3. 심평원 공식 자동수신 API — 공개 자료에서 확인 안 됨 (가능성 낮음, M0c에서 확인)

## 2. 법적·제도적 근거

- **고시**: 「요양급여비용 청구방법, 심사청구서·명세서서식 및 작성요령」 (보건복지부 고시) — 전자문서 구조는 심사평가원장이 공고하는 **「건강보험급여비용 전자문서」** 규격에 따름
- 정보통신망 청구의 전자문서 효력·도달시기는 「정보통신망 이용촉진 및 정보보호 등에 관한 법률」 준용
- 심평원 → 요양기관 전송 전자문서 종류:
  - 요양급여비용 **심사결과통보서**
  - 원외처방약제비 심사결과통보서 / 심사결과(추가)통보서
  - 요양급여비용 / 의료급여비용 / 원외처방약제비 **정산심사내역서**
- 의료급여(보호)는 별지 제2호서식 「의료급여비용심사결과통보서」 별도 (구조 유사)

## 3. 심사결과통보서 구조 (공개 자료 기반 — 실물 검증 필요)

### 3.1 계층 구조

```
심사결과통보서 (접수번호 단위)
├── [총괄] 청구 기본 정보
│     요양기관번호, 접수번호, 진료년월, 심사결정일,
│     청구액 합계, 심사결정액 합계, 지급불능 사항, 증감 사항
├── [명세서 단위] (명일련번호 = 명세서 일련번호로 식별)
│     환자 식별, 청구금액, 조정금액, 심사결정금액
└── [조정 내역] (명세서 하위, 항목/줄 단위)
      조정코드, 조정금액, 심사조정 사유
```

### 3.2 주요 항목 의미

| 항목 | 의미 | ERP 매핑 대상 |
|------|------|--------------|
| 접수번호 | 청구 건의 심평원 접수 식별자 | 청구 배치 키 |
| 명일련번호 (명세서 일련번호) | 환자별 명세서 식별자 | **환자별 분류 키 (FR-39)** |
| 청구금액 | 요양기관이 청구한 원금액 | 청구 원장 |
| 조정금액 | 심사 결과 조정(삭감)된 금액 | **삭감 분류·통계 (FR-39, FR-48)** |
| 심사결정금액 | 최종 지급 대상 금액 | 수납/재무 대사 |
| 조정코드(조정사유코드) | 삭감 사유 분류 (예: "요양급여 기준 초과" 계열) | **삭감 사유 마스터 (코드 테이블 필요)** |
| 지급불능 사항 | 지급 불가 건 (보완청구 대상) | 보완청구 워크플로우 |

### 3.3 구분 개념 (업무 분류)

- **심사조정 건**: 심사로 금액이 조정(삭감)된 건 → 이의신청/재심사조정청구 대상
- **지급불능 건**: 지급 자체가 불가한 건 → 보완청구 대상
- 특정내역 메모: `MX999`(명세서 단위 기재 메모), `JX999`(처방 단위 특정내역) — 청구 시 소명용

## 4. 업무 기한 (Claims 워크플로우 설계 반영 필수)

| 업무 | 기한 | FR 반영 |
|------|------|---------|
| **재심사조정청구 / 이의신청** (심사조정 건) | 통보서 **도달일로부터 90일 이내** | FR-40 이의신청 워크플로우에 **기한 카운트다운·임박 알림** 추가 필요 |
| **보완청구** (지급불능 건) | 통보서 도달 후 **3년 이내** | 지급불능 건 관리 화면에 기한 표시 |

> 💡 90일 기한은 In-app 알림(FR-26)과 연동해 "이의신청 기한 임박" 알림을 권장 — 설계 단계에서 FR 보강.

### 수신 확인 절차 (요양기관업무포털 기준, 수동 경로)

1. 요양기관업무포털 공인인증서 로그인 → [진료비 청구] → [심사진행과정(결과통보서)조회]
2. 접수/진료 년월 조회 → 접수번호 클릭 (공단=건강보험 / 보호=의료급여)
3. 청구액·심사결정액·지급불능·증감 확인 → 심사조정 건은 명일련번호 클릭 → 조정코드/조정금액/사유 확인
