# 병원 ERP 세부 기능 개선 검토 계획서

> **목적**: 운영 중인 ERP의 28개 화면·10개 백엔드 모듈을 기능 단위로 점검하여, 각 기능에 개선
> 여지가 있는지 체계적으로 검토하고 우선순위화한다. "무엇을 더 좋게 만들 수 있는가"의 목록과
> 검토 방법을 정의한다.
> **작성일**: 2026-06-08 · **대상 범위**: 화면 28 · API ~105 · 테스트 43파일 · 마이그 0014
> **현 상태**: Phase 1 + 재무 확장 + 2차 + Phase 2 골격 완료(PR #1~#34)

---

## 1. 검토 차원 (6축)

모든 기능을 아래 6개 축으로 점검한다.

| 축 | 점검 질문 | 도구 |
|----|----------|------|
| **F 기능 완성도** | 업무 플로우가 끝까지 닫히는가? 빠진 액션(수정·삭제·출력)은? | gap-detector, 수기 |
| **U UX·일관성** | 검색·필터·페이지네이션·빈상태·로딩·에러 처리가 일관적인가? | design-validator |
| **D 데이터 정합** | 집계·전표·상태전이가 정확한가? 자가검증이 있는가? | code-analyzer |
| **P 성능** | N+1·풀스캔·대량 렌더 병목은? | code-analyzer |
| **A 권한·보안** | 행 scope(부서/본인) 합성, 민감정보 마스킹이 맞는가? | security-architect |
| **V 검증** | 단위/통합 테스트 커버리지, 경계조건은? | qa-strategist |

> 화면 풍부도(코드 라인수)는 **개선 여지의 1차 신호**로만 사용. 얇은 화면(근태 40·증명서 42·
> 알림 43·감사 45·세무 51·ABC 55줄)을 우선 점검 후보로 표시.

| # | 항목 | 현황 | 개선 |
|---|------|------|------|
| X1 | **출력(Excel/PDF)** | 직원·근무표·급여 일부만 | 결산·재무제표·세무신고·증명서 등 **출력 일관 적용** |

## 4. 우선순위 (개선 착수 순서)

### P1 — 업무 공백(얇은 화면) 보강 🔴
1. **세무 신고서식 출력** — 신고 실무 직결
2. **증명서 PDF 출력** — 발급 실무 직결
3. **근태 집계·시각화** — 급여 연계 기반
4. **감사·접속기록 필터·검색** — 보안 운영 필수

### P2 — 횡단 일관성 🟡
5. **출력(Excel/PDF) 일관 적용**(X1) — 결산·재무제표·세무
6. **차트 시각화**(X3) — BI·재무 aging
7. **목록 검색·필터 공통화**(X2)

### P3 — 화면별 기능 심화 🟡
8. 재무제표 전년/전월 비교, 원가 수익성, ABC 동인 UI
9. 예약 캘린더, 환자 검색 고도화, 직원 상세·수정

### P4 — 기반 품질 🟢
10. 빈상태·로딩 일관화(X4), 통합 알림센터(X5), 반응형(X6)

## 5. 검토 방법론 (bkit PDCA)

| 단계 | 도구 | 산출 |
|------|------|------|
| **Check-1 설계 합치도** | `bkit:gap-detector` (화면↔설계) | 모듈별 Match Rate |
| **Check-2 코드 품질** | `bkit:code-analyzer` (모듈별 정밀) | 결함 목록(심각도) |
| **Check-3 UX 일관성** | `bkit:design-validator` | 일관성 위반 목록 |
| **Check-4 QA** | `bkit:qa-strategist` + 운영 검증 | 시나리오 결과 |
| **Act 개선** | `/pdca iterate` 또는 직접 구현 | PR |

권장 실행: **P1 4건을 먼저 구현**(직접) → 누적 후 `code-analyzer`로 재검증 → P2 횡단 개선 →
마일스톤 `report-generator`. 각 항목은 독립 PR로 분리(현 워크플로우 유지).
